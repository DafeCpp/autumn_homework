# Косарайю и Тарьян: компоненты сильной связности

Из корня репозитория:

```bash
./visualize scc
```

Команда собирает оба алгоритма, проверяет ответы, записывает шаги и запускает
просмотрщик: **http://localhost:8765**. В Codespaces откройте **Ports → 8765 → Open in Browser**.
Нужны Node.js 24+, CMake, C++-компилятор, GoogleTest и Python 3 — как для существующего BFS.
Установка npm-пакетов для запуска не нужна.

В списке выберите `kosaraju_visualization / three_components`, затем
`tarjan_visualization / three_components`: это один и тот же ориентированный граф.
Доступны шаг вперёд/назад, ползунок, воспроизведение, изменение скорости,
перетаскивание вершин, «Граф и дерево» и полноэкранный режим.
Цвет и подпись `КСС N` обозначают компоненту; номера присваиваются в порядке
обнаружения и **могут различаться у двух алгоритмов**. Сравнивайте состав компонент.

Отдельный алгоритм: `./visualize kosaraju` или `./visualize tarjan`.
Для обновления записей без остановки сервера: `./visualize scc --prepare-only`.
Другой порт: `./visualize scc --port 8766`. Остановка — Ctrl+C.

## Сценарий объяснения

1. **Косарайю, первый проход.** DFS идёт по исходным стрелкам. `finish` — порядковый
   номер выхода из вершины; список выходов виден над панелью воспроизведения.
2. **Переход ко второму проходу.** Стрелки разворачиваются, заголовок меняется на
   «Обратный граф Gᵀ», дерево первого прохода очищается. Порядок выходов сохраняется.
3. **Косарайю, второй проход.** Корни выбираются по убыванию `finish`.
   Каждый новый DFS выделяет одну КСС. Перемотка назад восстанавливает исходные стрелки.
4. **Тарьян.** `index` — номер открытия (с 1), `lowlink` — минимум, обновляемый
   при возврате от ребёнка или по ребру к вершине в стеке КСС.
   После ребёнка берём его `lowlink`, по ребру в стек — `index` конца ребра.
   На графе и дереве под каждой вершиной показаны `tin` (= `index`) и `low`
   (= `lowlink`) текущего шага. До входа в вершину стоят прочерки; при перемотке
   значения восстанавливаются. Подпись КСС находится ниже этих двух строк.
5. Стек КСС показан от дна к вершине. `on_stack` и `stack_position` доступны в таблице.
   Жёлтая вершина уже завершила DFS, но остаётся в стеке КСС. Синие вершины находятся
   в активной цепочке DFS. Это два разных стека.
6. При `lowlink[v] == index[v]` снимаем вершины до `v` включительно: найдена КСС.
   Рёбра в уже выделенную КСС не меняют `lowlink`.

В режиме дерева пунктир у Тарьяна означает **нетревесное ребро**, которое не
обязательно ведёт к предку: его конец может уже выйти из DFS, оставаясь в стеке КСС.

## Примеры

| Тест | Что показать |
| --- | --- |
| `three_components` | Три цикла, соединённые в цепочку; разные порядки выделения КСС. |
| `stack_cross_edge` | Ребро к вершине, вышедшей из DFS, но оставшейся в стеке; затем ребро в готовую КСС. |
| `dag` | Каждая вершина — отдельная КСС. |
| `disconnected` | Несвязный граф и изолированные вершины. |
| `loops_parallel` | Петли и кратные ориентированные рёбра. |
| `single` | Одна вершина без рёбер. |

Свой граф добавьте файлом `.in` в `examples/kosaraju_visualization/tests/`
и/или `examples/tarjan_visualization/tests/`. Формат: `n m`, затем `m` пар `u v`
(стрелка `u → v`); вершины от 1. Добавьте эталон `.out` для проверки ответа.
В выводе у каждой вершины стоит **минимальный номер вершины её КСС**.
Например, для `three_components`: `1 1 1 4 4 6 6 6`.
Это каноническая нумерация для сравнения ответов, отличная от учебной нумерации
компонент на шагах. После добавления графа повторите команду запуска.

## Код и проверки

- [scc.hpp](src/scc.hpp) — интерфейс функций `Kosaraju` и `Tarjan`.
- [scc.cpp](src/scc.cpp) — обе реализации; явный стек кадров заменяет рекурсию.
- [main.cpp](src/main.cpp) — общий ввод/вывод и подключение записи.
- [test.cpp](src/test.cpp) — граничные случаи, цепь/цикл из 100000 вершин и
  300 случайных графов со сравнением с независимым эталоном достижимости.

Оба алгоритма работают за O(V+E) времени и памяти без учёта вывода записи.
Можно вызвать `Kosaraju(n, edges)` или `Tarjan(n, edges)` без просмотрщика.
Они возвращают вектор размера `n+1`; индекс 0 не используется.

Ограничения ввода программы: 1 ≤ n ≤ 200000, 0 ≤ m ≤ 200000.
Просмотрщик: до 500 вершин, 2000 рёбер; запись ограничена 50000 событиями и ~8 МиБ.
При достижении лимита алгоритм завершит расчёт, но запись будет неполной.

```bash
./visualize scc --prepare-only
npm --prefix tools/graph_viewer test
```
