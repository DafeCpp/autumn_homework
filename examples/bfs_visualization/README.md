# BFS: расстояния от вершины 1

Учебный пример подключения записи шагов к своему решению. Граф отображается
так же, как файловые тесты остальных задач: вершины и рёбра, без специальной сетки.

## Задача

Дан неориентированный невзвешенный граф. Найдите расстояние от вершины `1`
до каждой вершины; для недостижимых выведите `-1`.

Ввод: `n m`, затем `m` пар `u v`. Вершины нумеруются с 1. Допустимы петли,
кратные рёбра и несвязный граф. `1 ≤ n ≤ 200000`, `0 ≤ m ≤ 200000`.
Для просмотра выбирайте небольшие тесты (до 500 вершин и 2000 рёбер).
Вывод: `n` расстояний в порядке номеров вершин, в одной строке.

```text
6 4
1 2
1 3
2 4
3 5
```

Ответ: `0 1 1 2 2 -1`.

## Запуск в Codespaces

Все команды выполняются **в терминале Codespace**, из корня репозитория.
В новом Codespace Node.js 24 устанавливается настройкой devcontainer.
В существующем Codespace после обновления ветки выполните **Codespaces: Rebuild Container**.

Соберите только учебный пример:

```bash
cmake -S examples/bfs_visualization -B build/examples/bfs_visualization
cmake --build build/examples/bfs_visualization
python3 scripts/run_cases.py --example bfs_visualization --trace-dir
npm --prefix tools/graph_viewer start
```

В панели **Ports** откройте порт **8765 → Open in Browser**.
Оставьте видимость **Private**. Ничего скачивать на свой компьютер не нужно.
Просмотрщик работает без `npm install`: сервер использует стандартную библиотеку Node.

Выберите `bfs_visualization / chain`. Нажимайте «Следующий шаг», перемещайте
ползунок или включите воспроизведение. В таблице видны расстояния, цветом —
текущая вершина, вершины в очереди и обработанные вершины. Зелёные рёбра образуют дерево BFS.

Откройте второй терминал Codespace, измените решение, пересоберите и снова
запустите `run_cases.py`. Страница проверяет новые записи каждые 3 секунды
и сохраняет положение вершин. Сервер остановится по Ctrl+C; после перезапуска
откройте тот же порт. Файлы записей остаются в `.graph-traces/`.

Обычная проверка без записи:

```bash
python3 scripts/run_cases.py --example bfs_visualization
```

Пример также включён в общую сборку CMake; отдельная сборка выше не требует GTest.
Используйте либо общую сборку, либо отдельную: если переключаете способ,
задайте новый каталог сборки и передайте его через `--build-dir` раннеру.

## Где добавлены вызовы

Сравните [обычное решение](src/plain.cpp) и [решение с записью](src/main.cpp).
Алгоритм и ответ одинаковые. Отличается только подключение `graph_trace.hpp`
и обращения к `trace`.

1. Создайте `graph_trace::Recorder trace` и вызовите `trace.graph(n)`.
2. При чтении рёбер вызовите `trace.add_edge(id, u, v)`. ID — номер ребра
   во входном файле, **с нуля**, даже если вершины нумеруются с 1.
3. После добавления вершины в очередь запишите `trace.node(v, "queued")`.
4. После извлечения из очереди — `trace.node(v, "active")`.
5. После вычисления расстояния — `trace.value(v, "distance", distance[v])`.
6. После обработки соседей — `trace.step("Обработали соседей")`.
   Этот вызов создаёт кадр со всеми изменениями с предыдущего шага.
7. Пометьте вершину `done`. Она станет обработанной в следующем кадре.
8. В конце добавьте финальный `step`, затем `finish()`.

Для упражнения добавьте отображение размера очереди у текущей вершины:

```cpp
trace.value(v, "queue_size", static_cast<int>(queue.size()));
```

Поставьте вызов перед `trace.step(...)`. Новое значение появится в таблице.
Порядок внутри очереди просмотрщик не показывает: цветом отмечается её состав.

## Подключение к своему заданию

В задачах, связанных с библиотекой `Utils`, заголовок уже доступен:

```cpp
#include "graph_trace.hpp"

graph_trace::Recorder trace;
trace.graph(n, true, 0);  // ориентированный граф, вершины от 0
```

Для `task_01` используйте `true, 0`, для `task_02` — `true, 1`,
для `task_03` — `false, 1`. Сохраняйте ориентацию рёбер входного файла.
Для `task_01` стрелка `a → b` означает «a зависит от b».

```bash
python3 scripts/run_cases.py --tasks task_03 --trace-dir --save-actual
```

Без вызовов записи будет доступен сам граф теста. Файлы `.in/.out` остаются
в обычных `task_XX/tests/`. В просмотрщике сейчас поддержаны `task_01–03` и BFS.
Для `task_03` можно отдельно включить подсветку эталона или сохранённого
несовпавшего ответа. `.out.actual` создаётся флагом `--save-actual`.

Режим «Эксперимент» позволяет отключать рёбра и вершины кликом и сравнивать
число компонент до и после. Он доступен только для неориентированных графов.
Кнопка «Восстановить граф» отменяет отключения.

## Ограничения записи

- `GRAPH_TRACE` задаёт путь отдельного JSONL-файла. Раннер назначает его для каждого теста.
- Без этой переменной файл не создаётся. Ответ алгоритма пишется в `stdout` как обычно.
- Каждое событие записывается с переводом строки и сбросом буфера; после падения
  программы полные кадры можно открыть, если описание графа уже записано целиком.
- Запись ограничена 50000 событиями и примерно 8 МиБ. Просмотрщик показывает предупреждение.
- Выполняйте измерения скорости и памяти отдельно: запись шагов добавляет накладные расходы.
- Большие графы не обрезаются молча: просмотрщик предлагает выбрать меньший тест.
- `.graph-traces/` не включается в Git. Изменения файлов ввода требуют новой записи.

Подробности формата и проверки самого инструмента: [просмотрщик](../../tools/graph_viewer/README.md).
