# BFS: расстояния от вершины 1

Учебный пример подключения записи шагов к своему решению. Граф отображается
так же, как файловые тесты остальных задач: вершины и рёбра, без специальной сетки.

## Задача

Дан неориентированный невзвешенный граф. Найдите расстояние от вершины `1`
до каждой вершины; для недостижимых выведите `-1`.

Ввод: `n m`, затем `m` пар `u v`. Вершины нумеруются с 1. Допустимы петли,
кратные рёбра и несвязный граф. `1 ≤ n ≤ 200000`, `0 ≤ m ≤ 200000`.
Для просмотра выбирайте небольшие тесты (до 500 вершин и 2000 рёбер).
Вывод: `n` расстояний в порядке номеров вершин, в одной строке.

```text
6 4
1 2
1 3
2 4
3 5
```

Ответ: `0 1 1 2 2 -1`.

## Запуск в Codespaces

Все команды выполняются **в терминале Codespace**, из корня репозитория.
В новом Codespace Node.js 24 устанавливается настройкой devcontainer.
В существующем Codespace после обновления ветки выполните **Codespaces: Rebuild Container**.

Запустите одной командой:

```bash
./visualize
```

Скрипт соберёт BFS, проверит тесты, запишет шаги и запустит просмотрщик.
Установка npm-пакетов не нужна. Для своего решения используйте
`./visualize task_03` (также поддержаны `task_01` и `task_02`).
Если тесты решения не пройдут, просмотрщик всё равно откроется для разбора.
Если файловых тестов нет, сначала добавьте их в каталог задачи.

В панели **Ports** откройте порт **8765 → Open in Browser**.
Оставьте видимость **Private**. Ничего скачивать на свой компьютер не нужно.
Просмотрщик работает без `npm install`: сервер использует стандартную библиотеку Node.

Выберите `bfs_visualization / chain`. Нажимайте «Следующий шаг», перемещайте
ползунок или включите воспроизведение. В таблице видны расстояния, цветом —
текущая вершина, вершины в очереди и обработанные вершины. Зелёные рёбра образуют дерево BFS.

После изменения решения остановите скрипт через Ctrl+C и снова выполните
`./visualize` (для своей задачи — с тем же именем задачи). Сборка обновится,
тесты запустятся заново. Откройте тот же порт или обновите страницу.
Файлы записей остаются в `.graph-traces/`.

Если хотите оставить сервер работающим, во втором терминале выполните
`./visualize --prepare-only` (или `./visualize task_03 --prepare-only`). Страница
подхватит новую запись в течение 3 секунд, сохранив расположение вершин.

Обычная проверка без записи:

```bash
python3 scripts/run_cases.py --example bfs_visualization --build-dir .graph-build/demo
```

Скрипт хранит отдельную сборку в `.graph-build/demo`, а сборку своих задач —
в `.graph-build/project`. Каталог `build/`, которым пользуется IDE, не затрагивается.
Пример и задачи используют GoogleTest, уже установленный в Codespace.
Пример также включён в общую сборку CMake.

## Структура примера и GTest

- [bfs.hpp](src/bfs.hpp) — интерфейс алгоритма и тип ребра.
- [bfs.cpp](src/bfs.cpp) — BFS и необязательная запись его шагов.
- [main.cpp](src/main.cpp) — чтение графа, вызов BFS с записью, вывод ответа.
- [plain.cpp](src/plain.cpp) — тот же запуск без записи шагов.
- [test.cpp](src/test.cpp) — тесты алгоритма на GoogleTest, как в остальных задачах.

Алгоритм реализован один раз. Он принимает число вершин и список рёбер,
возвращает вектор расстояний размера `n + 1`; элемент с индексом 0 не используется.
Недостижимые вершины имеют расстояние `-1`. Некорректное число вершин или
концы рёбер вызывают `std::invalid_argument`.

```cpp
const auto plain = bfs_example::Bfs(n, edges);  // без записи
auto trace = std::make_shared<graph_trace::Recorder>();
const auto recorded = bfs_example::Bfs(n, edges, trace);  // с записью
trace->Finish();
```

`./visualize` автоматически запускает и GTest, и файловые тесты.
Для запуска только уже собранных модульных тестов:

```bash
.graph-build/demo/examples/bfs_visualization/bfs_visualization_tests
```

Или через CTest:

```bash
ctest --test-dir .graph-build/demo/examples/bfs_visualization --output-on-failure
```

12 тестов проверяют отдельную вершину, цепочку, цикл, кратчайшие пути,
несвязность, направление обхода, петли и кратные рёбра, порядок входных рёбер,
длинную цепочку и некорректные входные данные. Они вызывают функцию BFS
напрямую; файловые тесты отдельно проверяют ввод и вывод программы.

## Где добавлены вызовы визуализации

`main.cpp` создаёт запись через `std::make_shared<graph_trace::Recorder>()`,
передаёт умный указатель алгоритму и вызывает `trace->Finish()` после его завершения.
BFS принимает `const std::shared_ptr<graph_trace::Recorder>&`, поэтому не копирует
умный указатель. По умолчанию указатель пустой — запись отключена. В `bfs.cpp` все обращения
к записи обёрнуты в `if (trace)`, поэтому тот же алгоритм работает без просмотрщика.

1. В начале BFS записываются `trace->Graph(n)` и рёбра через `trace->AddEdge(id, u, v)`.
   ID — номер ребра во входном файле, **с нуля**, даже если вершины нумеруются с 1.
2. После добавления вершины в очередь — `trace->Node(v, "queued")`.
3. После извлечения из очереди — `trace->Node(v, "active")`.
4. После вычисления расстояния — `trace->Value(v, "distance", distance[v])`.
5. После обработки соседей — `trace->Step("Обработали соседей")`.
   Этот вызов создаёт кадр со всеми изменениями с предыдущего шага.
6. Затем вершина помечается `done`. Она станет обработанной в следующем кадре.
7. В конце алгоритма создаётся финальный `step`.

Для упражнения добавьте отображение размера очереди у текущей вершины:

```cpp
if (trace) {
  trace->Value(v, "queue_size", static_cast<int>(queue.size()));
}
```

Поставьте вызов перед `trace->Step(...)`. Новое значение появится в таблице.
Порядок внутри очереди просмотрщик не показывает: цветом отмечается её состав.

## Подключение к своему заданию

Интерфейс находится в `lib/src/graph_trace.hpp`, реализация — в `lib/src/graph_trace.cpp`.
В задачах, связанных с библиотекой `Utils`, оба файла уже подключены:

```cpp
#include "graph_trace.hpp"

graph_trace::Recorder trace;
trace.Graph(n, true, 0);  // ориентированный граф, вершины от 0
```

Для `task_01` используйте `true, 0`, для `task_02` — `true, 1`,
для `task_03` — `false, 1`. Сохраняйте ориентацию рёбер входного файла.
Для `task_01` стрелка `a → b` означает «a зависит от b».

```bash
python3 scripts/run_cases.py --tasks task_03 --trace-dir --save-actual
```

Без вызовов записи будет доступен сам граф теста. Файлы `.in/.out` остаются
в обычных `task_XX/tests/`. В просмотрщике сейчас поддержаны `task_01–03` и BFS.
Для `task_03` можно отдельно включить подсветку эталона или сохранённого
несовпавшего ответа. `.out.actual` создаётся флагом `--save-actual`.

Режим «Эксперимент» позволяет отключать рёбра и вершины кликом и сравнивать
число компонент до и после. Он доступен только для неориентированных графов.
Кнопка «Восстановить граф» отменяет отключения.

## Ограничения записи

- `GRAPH_TRACE` задаёт путь отдельного JSONL-файла. Раннер назначает его для каждого теста.
- Без этой переменной файл не создаётся. Ответ алгоритма пишется в `stdout` как обычно.
- Каждое событие записывается с переводом строки и сбросом буфера; после падения
  программы полные кадры можно открыть, если описание графа уже записано целиком.
- Запись ограничена 50000 событиями и примерно 8 МиБ. Просмотрщик показывает предупреждение.
- Выполняйте измерения скорости и памяти отдельно: запись шагов добавляет накладные расходы.
- Большие графы не обрезаются молча: просмотрщик предлагает выбрать меньший тест.
- `.graph-traces/` не включается в Git. Изменения файлов ввода требуют новой записи.

Подробности формата и проверки самого инструмента: [просмотрщик](../../tools/graph_viewer/README.md).

### Дерево BFS

Выберите «Дерево обхода» над графом и переходите по шагам. Сплошное ребро
появляется при открытии новой вершины, пунктирное — при обнаружении
нетревесного ребра. В BFS это не обязательно обратное ребро к предку:
оно может соединять вершины одного уровня. Непосещённые вершины остаются
в нижнем ряду. В таблице `parent` показывает, из какой вершины открыли текущую.
