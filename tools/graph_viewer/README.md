# Просмотр графов и записей алгоритмов

TypeScript-сервер на Node.js 24, браузерный интерфейс на JavaScript/SVG.
Нет сторонних runtime-зависимостей, CDN, сборки интерфейса или отдельного Python-сервера.
Python используется только существующим `scripts/run_cases.py`.

Основной сценарий: [учебный BFS в Codespaces](../../examples/bfs_visualization/README.md).

## Запуск

Из корня репозитория:

```bash
npm --prefix tools/graph_viewer start
```

Порт 8765 настроен в devcontainer. Откройте **Ports → Open in Browser**,
оставив видимость Private. В уже существующем Codespace нужно пересобрать
контейнер после обновления конфигурации. Если порт занят:

```bash
npm --prefix tools/graph_viewer start -- --port 8766
```

Тогда добавьте порт 8766 в панели Ports. Для нестандартного каталога записей
передайте одинаковый `--trace-dir` раннеру и серверу (лучше абсолютный путь).
Флаг `--host` меняет адрес привязки, по умолчанию `127.0.0.1`.
Сервер запускается внутри Codespace; браузер использует только относительные
API-адреса через проброшенный порт.

[Справка GitHub о портах и приватности](https://docs.github.com/en/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace).

## Возможности

- Автоматическое чтение `*.in` из `task_01–03/tests`, корня этих задач и `examples/bfs_visualization/tests`.
- Ориентированные и неориентированные графы, петли, кратные рёбра, изолированные вершины.
- Нумерация с 0 или 1 задаётся адаптером задачи, не угадывается из входа.
- Перемещение вершин, масштабирование, перемещение поля.
- Перемотка событий, воспроизведение, таблица значений.
- Отключение вершин/рёбер неориентированного графа и подсчёт компонент.
- Подсветка ответа `task_03`, чтение `.out` и сохранённого `.out.actual`.
- Обновление записи каждые 3 секунды с сохранением расположения вершин.

Просмотрщик принимает до 500 вершин, 2000 рёбер и около 8 МиБ записи.
Для больших тестов выберите уменьшенный пример. Центральный каталог тестов
`--tests-layout central` пока не отображается: используйте тесты внутри задач.
Поддержка других форматов задач добавляется явным адаптером в `TASKS`.
`task_01` появится в списке, когда в его каталоге будут `.in`-тесты.

## Формат записи v1

Каждая строка — отдельный JSON-объект. Рёбра описываются один раз в порядке
входного файла, ID от 0. После описания графа идут изменения и границы кадров.

```jsonl
{"type":"header","version":1}
{"type":"graph","n":2,"first":1,"directed":false}
{"type":"add_edge","id":0,"from":1,"to":2}
{"type":"node","id":1,"state":"active"}
{"type":"value","id":1,"name":"distance","value":0}
{"type":"edge","id":0,"state":"tree"}
{"type":"step","message":"Обработали вершину 1"}
{"type":"end"}
```

Состояния: `idle`, `queued`, `active`, `done`, `tree`, `bridge`, `cut`.
`value` хранит числовые значения у вершины. `step` фиксирует кадр. Изменения
после последнего `step` не отображаются: перед `finish()` нужен финальный `step`.
`truncated` означает достижение лимита. Без `end` запись считается незавершённой.
Неполная последняя строка игнорируется, полные предыдущие шаги доступны.
Повреждённые события, неизвестные ID и другой граф вызывают предупреждение,
а сам граф теста остаётся доступен.

Сервер только читает данные, не запускает C++ и не изменяет репозиторий.
API выдаёт лишь тесты из каталога разрешённых задач, связанные ответы и записи;
произвольные пути и выход через символьные ссылки за разрешённые каталоги запрещены.
Строки и подписи интерфейс добавляет как текст, не как HTML.

## Проверки для разработчика

Нужны Node.js 24, C++-компилятор и Python 3 (для существующего раннера):

```bash
npm --prefix tools/graph_viewer ci
npm --prefix tools/graph_viewer run typecheck
npm --prefix tools/graph_viewer test
```

Тесты проверяют адаптеры, запись C++, совпадение ответов двух версий BFS,
интеграцию раннера, лимиты/обрыв записи, обратную перемотку, эксперименты
с графом и HTTP API. HTTP-тест открывает временный порт только на loopback.
Зависимости TypeScript и `@types/node` нужны только для проверки типов.
