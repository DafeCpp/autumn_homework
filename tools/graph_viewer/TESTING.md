# Проверка визуализатора перед PR

Все команды ниже выполняются из корня репозитория. Нужны Node.js 24 или новее,
Python 3, C++-компилятор, CMake и GoogleTest. В Codespaces зависимости уже есть
в контейнере проекта; после изменения его конфигурации выполните Rebuild Container.
`npm ci` устанавливает только инструменты проверки TypeScript, для просмотра npm-зависимости не нужны.

## Автоматические проверки

```bash
npm --prefix tools/graph_viewer ci
npm --prefix tools/graph_viewer run typecheck
python3 -m unittest discover -s scripts/tests -v
npm --prefix tools/graph_viewer test
./visualize --prepare-only
git diff --check
```

Python-тесты создают временные задачи и проверяют OK, Wrong Answer, Runtime Error
(включая код 124), настоящий таймаут, отсутствие эталона/программы, сохранение
диагностики и изоляцию одноимённых тестов. Файлы решений студентов не меняются.
Node-тесты проверяют API, недоступные/повреждённые отчёты, обновление результатов,
раскладку, запись C++, обратную перемотку и полный запуск через `./visualize`.
Последняя команда подготовки должна завершиться с кодом 0: 12 GTest и 10 файловых
тестов BFS. При добавлении новых тестов эти числа могут увеличиваться.

Эти проверки запускает workflow `.github/workflows/graph-visualization.yaml`.
Остальные обязательные проверки репозитория также должны пройти перед merge.

## Два сценария запуска

**Только тесты в терминале**, для уже собранного решения:

```bash
python3 scripts/run_cases.py --tasks task_03 --build-dir build --save-actual
```

Здесь `build/task_03/task_03` — исполняемый файл. Вывод содержит итог `Passed`
и вердикт каждого теста. Раннер не собирает программу и не открывает браузер.
Если нужно передать результаты и шаги в уже открытый просмотрщик, добавьте
`--trace-dir .graph-traces`. Само решение должно использовать Recorder для записи шагов.

**Сборка, тесты и визуализация одной командой**:

```bash
./visualize
# Или для своего решения:
./visualize task_03
```

Откройте `http://localhost:8765`. В Codespaces: Ports → 8765 → Open in Browser.
Без аргумента запускается готовый учебный BFS. Для задач отображаются их реальные
результаты; непройденные тесты не мешают открыть просмотрщик. Без Recorder будут
доступны граф и ответы, но не анимация алгоритма.

После изменения решения, в другом терминале:

```bash
./visualize task_03 --prepare-only
```

Это заново собирает и проверяет программу. Открытый просмотрщик обновляет данные
примерно раз в 3 секунды. Его сервер только читает файлы и сам программу не запускает.
Чтобы обновить BFS, используйте `./visualize --prepare-only`.
Если порт занят: `./visualize --port 8766`.

## Ручная проверка интерфейса

1. Запустите BFS. Слева должны быть настоящие вердикты и счётчик `10 / 10 OK`.
2. Откройте `cycle.in`. Проверьте следующие/предыдущие шаги, перемотку в начало,
   воспроизведение, паузу и скорость. Значения вершин должны меняться вместе с шагами.
3. Переключите «Граф», «Дерево», «Граф и дерево». В дереве не должны появляться
   ещё не записанные рёбра. Перетаскивание, масштаб и «Вместить» должны работать.
4. Проверьте все вкладки данных, панель снизу/справа, сворачивание, полный экран
   и выход из него. Выбранный тест и шаг должны сохраняться.
5. Откройте задачу без записи шагов: исходный граф доступен, проигрыватель отключён.

### Проверка Wrong Answer и собственного теста без изменения решений

Создайте файлы `examples/bfs_visualization/tests/custom/review_case.in` и
`examples/bfs_visualization/tests/custom/review_case.out`. Для входа:

```text
3 2
1 2
2 3
```

В `.out` временно запишите `wrong`, затем выполните `./visualize --prepare-only`.
Команда должна вернуть код 1 и показать Wrong Answer. В просмотрщике раскройте
«Свои тесты» и выберите `review_case.in`: откроется его граф и несовпадающие ответы.
Счётчик встроенных тестов останется `10 / 10 OK` — свои тесты считаются отдельно.

Исправьте `.out` на `0 1 2` с переводом строки. До перезапуска вердикт должен стать
«Нужно перезапустить». После `./visualize --prepare-only` он сменится на OK, старый
`.out.actual` будет удалён. Удалите только созданные для этой проверки два файла
`review_case.in` / `review_case.out` и повторите подготовку. При удалении выбранного
теста интерфейс переключается на доступный тест, а если тестов больше нет — очищается.

Перед коммитом проверьте `git status --short`: временные тесты не должны попасть
в PR. `.graph-build`, `.graph-traces`, `node_modules` и `.out.actual` игнорируются Git.
