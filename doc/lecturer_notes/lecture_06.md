## Откуда начинаем

Лекция 5 пройдена. Хиерхольцера только обзорно повторили, поскольку студенты знают его из дискретной математики. Дополнительно разобран A*. **Дейкстра и потенциалы ещё впереди** — это основа сегодняшней пары. Введение в A*, эйлеровы маршруты и планарность не повторяем. Доказательство Тарьяна остаётся на конец семестра при наличии времени.

Фраза для начала: «В A* мы выбирали вершину по сумме пройденного расстояния и оценки оставшегося пути. Сегодня уберём эвристику и строго разберём, почему можно окончательно зафиксировать ближайшую вершину. Затем вернём эвристику через изменение весов рёбер».

Обозначения: `n = |V|`, `m = |E|`, `s` — источник, `t` — цель, `w(u,v)` — вес дуги, `δ(s,v)` — истинное кратчайшее расстояние, `d[v]` — текущая оценка. По умолчанию граф ориентированный и хранится списками смежности; неориентированное ребро представляется двумя дугами. До раздела о потенциалах все веса неотрицательны, нулевые веса разрешены.

## 1. Постановка и релаксация

Нужно найти расстояния из `s` во все достижимые вершины. У недостижимых вершин расстояние `∞`. Для поиска только до `t` можно завершиться раньше, но лишь когда её расстояние окончательно зафиксировано.

```text
d[s] = 0
у остальных d[v] = ∞

relax(u, v, w):
    if d[u] != ∞ and d[u] + w < d[v]:
        d[v] = d[u] + w
        parent[v] = u
```

Любая конечная оценка — длина некоторого уже найденного маршрута. Поэтому `d[v] >= δ(s,v)`: оценки улучшаются сверху. Релаксация сама по себе не определяет порядок обработки вершин; именно порядок отличает алгоритмы.

Вопрос из прошлого занятия: «Что получится из приоритета A* `g[v] + h[v]`, если `h = 0`?» Ответ: выбор вершины с минимальной текущей длиной пути — идея Дейкстры.

## 2. Дейкстра: алгоритм и сквозной пример

Поддерживаем множество зафиксированных вершин. На каждом шаге выбираем незафиксированную вершину `u` с минимальным конечным `d[u]`, фиксируем её и релаксируем все исходящие дуги. Если конечных оценок больше нет, остальные вершины недостижимы.

### Пример A

```text
s → a (7), s → b (2), s → t (20)
b → a (1), b → c (6), b → t (10)
a → c (2)
c → t (3)
z — изолированная вершина
```

| После обработки | d[a] | d[b] | d[c] | d[t] | d[z] |
|---|---:|---:|---:|---:|---:|
| s | 7 | 2 | ∞ | 20 | ∞ |
| b | 3 | 2 | 8 | 12 | ∞ |
| a | 3 | 2 | 5 | 12 | ∞ |
| c | 3 | 2 | 5 | 8 | ∞ |
| t | 3 | 2 | 5 | 8 | ∞ |

Порядок фиксации: `s, b, a, c, t`. Кратчайший путь до `t`: `s → b → a → c → t`, длина 8.

Вопросы по рисунку:

- Почему нельзя остановиться при первом обнаружении `t`? Тогда получили бы 20 вместо 8.
- Окончательно ли значение `d[a] = 7` после обработки `s`? Нет, вершина ещё не зафиксирована.
- В какой момент `d[c] = 5` становится окончательным? При выборе `c` как ближайшей незафиксированной вершины.

## 3. Доказательство корректности

Доказываем индукцией: у каждой зафиксированной вершины `v` оценка равна `δ(s,v)`.

**База:** первым фиксируется `s`, расстояние до неё равно 0 при неотрицательных весах.

**Шаг:** пусть выбирается вершина `u` с минимальным конечным `d[u]`. Возьмём кратчайший путь из `s` в `u`. Пусть `y` — первая ещё незафиксированная вершина на нём, `x` — её предшественник. Случай `u = s` уже разобран.

В момент фиксации `x` по предположению индукции `d[x] = δ(s,x)`, а дуга `x → y` была отрелаксирована. Префикс кратчайшего пути тоже кратчайший, поэтому:

```text
d[y] <= δ(s,x) + w(x,y) = δ(s,y)
```

Конечные оценки не меньше истинного расстояния, значит `d[y] = δ(s,y)`. По выбору `u` и неотрицательности весов оставшегося участка пути:

```text
δ(s,u) <= d[u] <= d[y] = δ(s,y) <= δ(s,u)
```

Все неравенства обращаются в равенства, поэтому `d[u] = δ(s,u)`.

**Где использовали неотрицательность?** В сравнении `δ(s,y) <= δ(s,u)`: оставшийся участок не может уменьшить длину пути. Нулевые веса не мешают; при равных оценках порядок выбора произвольный.

Если нет незафиксированной вершины с конечной оценкой, достижимых незафиксированных вершин тоже нет: на пути к такой вершине существовал бы первый выход из зафиксированной части, уже давший конечную оценку.

## 4. Реализации и сложность

### Выбор минимума массивом

Храним `fixed[v]`. Не более `n` раз линейным просмотром выбираем минимум среди незафиксированных вершин; если минимум `∞`, завершаем. Все исходящие дуги просматриваются суммарно один раз.

Время `O(n² + m)`, дополнительная память `O(n)` без хранения графа. Для простого плотного графа обычно пишут `O(n²)`. При матрице смежности время и память — `O(n²)`.

### Бинарная куча с повторными записями

В этой реализации не уменьшаем ключ внутри кучи: при улучшении добавляем новую пару, старую оставляем до извлечения. Куча должна извлекать **минимальную** пару по расстоянию.

```text
d = [∞] * n
parent = [-1] * n
parentEdge = [-1] * n
d[s] = 0
heap = min_heap([(0, s)])

while heap is not empty:
    (du, u) = heap.pop_min()
    if du != d[u]:
        continue
    # Здесь u фиксируется; повторного улучшения при w >= 0 не будет.
    # Для задачи только до t можно завершиться здесь, если u == t.
    for (v, w, id) in adj[u]:
        if du + w < d[v]:
            d[v] = du + w
            parent[v] = u
            parentEdge[v] = id
            heap.push((d[v], v))
```

В примере A запись `(7,a)` устареет после добавления `(3,a)`. При извлечении `(7,a)` исходящие дуги `a` заново не просматриваем. Строгое `<` не добавляет повторных записей при равенстве расстояний, в том числе на нулевых циклах.

| Реализация | Время | Дополнительная память без графа |
|---|---|---|
| Массив + списки смежности | `O(n² + m)` | `O(n)` |
| Бинарная куча с уменьшением ключа | `O((n + m) log(n + 1))` | `O(n)` |
| Бинарная куча с повторными записями, код выше | `O(n + m log(m + 2))` | `O(n + m)` |

У версии с повторными записями не более `m` успешных релаксаций, куча может хранить `O(m)` записей. Для простого графа `m = O(n²)`, поэтому привычная оценка `O((n + m) log(n + 1))` также корректна. При произвольном числе параллельных дуг различие `log m` и `log n` не скрываем. Реализацию уменьшения ключа подробно не разбирать: таблица нужна для честного сравнения.

## 5. Восстановление пути и дерево кратчайших путей

При каждом **строгом улучшении** обновляем предка и идентификатор ребра. Для достижимой цели идём от `t` по предкам до `s`, затем разворачиваем последовательность. При `d[t] = ∞` пути нет; при `s = t` ответ состоит из одной вершины.

```text
if d[t] == ∞:
    report "Пути нет"
else:
    path = []
    v = t
    while v != -1:
        path.push(v)
        v = parent[v]
    path.reverse()
```

У каждой достижимой вершины, кроме `s`, окончательный предок был зафиксирован раньше неё. Поэтому даже при нулевых весах циклов в цепочке предков нет. Получаем дерево кратчайших путей на достижимых вершинах; недостижимые в него не входят. Это дерево зависит от разрешения равенств и не обязано быть единственным. После досрочного выхода по `t` гарантирован путь до `t`, но не окончательность всех остальных оценок.

Практические замечания:

- Не отмечать вершину окончательной при добавлении в кучу.
- При поиске пути до цели останавливаться на её актуальном извлечении, после проверки устаревшей записи.
- Не релаксировать из числового `INF`. В коде подобрать тип и `INF` по ограничениям, чтобы сумма `du + w` не переполнялась.
- Для параллельных дуг сохранять `parentEdge`, если нужен именно список рёбер.
- Не менять предка на равенстве «для красоты»: на нулевых циклах это может испортить восстановление.

## 6. Потенциалы: меняем веса, сохраняя лучшие пути

Потенциал — произвольная **конечная** функция `p: V → R`. Всю лекцию используем одно соглашение:

```text
w_p(u,v) = w(u,v) + p(u) - p(v)
```

Для пути `P` из `s` в `t` промежуточные потенциалы сокращаются:

```text
w_p(P) = w(P) + p(s) - p(t)
```

У всех путей с одинаковыми концами прибавка одинакова, поэтому их порядок по весу и множество кратчайших путей сохраняются. Однако веса путей к **разным** целям могут изменить взаимный порядок.

Если для всех дуг `w_p(u,v) >= 0`, к изменённому графу применима Дейкстра. Из найденных расстояний возвращаем исходные:

```text
δ(s,v) = δ_p(s,v) - p(s) + p(v)
```

Недостижимые вершины остаются недостижимыми. Сначала доказать сохранение путей, затем отдельно проверить неотрицательность: не всякий потенциал делает веса неотрицательными.

### Пример B: отрицательная дуга, подходящий потенциал

```text
s → a (2), s → b (5), b → a (-4), a → t (3), b → t (6)
p(s) = 0, p(a) = -4, p(b) = 0, p(t) = -1
```

| Дуга | Исходный вес | Новый вес |
|---|---:|---:|
| s → a | 2 | 6 |
| s → b | 5 | 5 |
| b → a | -4 | 0 |
| a → t | 3 | 0 |
| b → t | 6 | 7 |

В новом графе расстояние от `s` до `t` равно 5 по `s → b → a → t`. В исходном — `5 - 0 + (-1) = 4`, что совпадает с суммой `5 - 4 + 3`.

Потенциал здесь дан готовым. Как находить такой потенциал при отрицательных весах, обсудим после Форда—Беллмана при переходе к Джонсону; сегодня не создаём впечатления, что это бесплатное преобразование.

### Почему отрицательный цикл нельзя исправить потенциалом

На цикле начальная и конечная вершины совпадают, значит сумма весов вообще не меняется. Если исходный цикл отрицателен, все его дуги после перевзвешивания не могут стать неотрицательными одновременно.

## 7. Связь с уже известным A* — 8 минут

Не повторять постановку A*, его код и примеры поиска. Восстановить `f[v] = g[v] + h[v]` и проверить, как этот приоритет возникает из потенциала.

Для монотонной (согласованной) эвристики:

```text
h(u) <= w(u,v) + h(v),    h(t) = 0
p(v) = -h(v)
w_p(u,v) = w(u,v) - h(u) + h(v) >= 0
```

Стоимость уже найденного пути из `s` в `v` после перевзвешивания:

```text
g_p[v] = g[v] - h(s) + h(v) = f[v] - h(s)
```

Приоритеты различаются на одну константу, поэтому A* с такой эвристикой соответствует Дейкстре на неотрицательных изменённых весах. Это объясняет, почему окончательно обработанную вершину не нужно открывать заново.

**Контроль знака:** если взять точную оценку `h(v) = δ(v,t)`, то из неравенства треугольника `h(u) <= w(u,v) + h(v)` следует неотрицательность именно `w - h(u) + h(v)`. В нашем соглашении потенциал равен **минус** расстоянию до цели. Используем этот пример только там, где расстояние до цели конечно: подставлять `∞` в потенциал нельзя. Точные расстояния до цели — теоретический ориентир, а не способ бесплатно ускорить задачу, в которой они ещё неизвестны.

Допустимость `h(v) <= δ(v,t)` и монотонность — разные условия. Монотонность вместе с `h(t)=0` влечёт допустимость для вершин, достигающих цели, суммированием неравенств вдоль пути. Одной допустимости для безусловного закрытия вершины недостаточно; при несогласованной эвристике могут потребоваться повторные открытия. Это уточнение к уже известному алгоритму, а не новый блок о A*.

## 8. Контрольные вопросы

| Вопрос | Ответ |
|---|---|
| Почему `d[v]` — верхняя, а не нижняя оценка? | это вес конкретного найденного маршрута |
| Где нужны неотрицательные веса в доказательстве? | оставшийся участок кратчайшего пути не уменьшает длину |
| Можно ли остановиться, впервые добавив цель в кучу? | нет, её оценка ещё может улучшиться |
| Зачем пропускать устаревшие записи? | исходящие дуги не должны заново обрабатываться из старой оценки |
| Дейкстра работает с нулевыми рёбрами? | да; строгая релаксация сохраняет корректную работу с равенствами |
| Любой потенциал делает веса неотрицательными? | нет; это отдельное условие на каждую дугу |
| Изменится ли вес цикла после перевзвешивания? | нет, потенциалы сократятся полностью |
| Какой знак у потенциала для эвристики A*? | `p = -h` при формуле `w_p = w + p(u) - p(v)` |

## 9. Резерв на 5 / 10 / 20 минут: отрицательные веса

### Блок A — 5 минут: где ломается Дейкстра

Возвращаемся к примеру B **с исходными весами**. Алгоритм с окончательной фиксацией вершин выберет после `s` вершину `a` с оценкой 2, хотя путь `s → b → a` имеет длину 1. Ошибка уже в фиксации `a`; разрешение повторных обработок превращает алгоритм в другой процесс, к которому прежние доказательство и оценка времени не относятся.

Отрицательная дуга ещё не означает отрицательный цикл: пример B — DAG. Если же из `s` достижим отрицательный цикл, а из него достижима `t`, стоимость маршрутов из `s` в `t` не ограничена снизу. Для этой цели пишем `-∞`; недостижимый отрицательный цикл ответ из `s` не портит.

**Точка остановки:** различаем отрицательную дугу, цикл и его влияние на конкретную цель. Алгоритм для отрицательных весов ещё не введён.

### Блок B — ещё 5 минут: динамика по числу рёбер

`D_k[v]` — минимальная стоимость маршрута из `s` в `v` по **не более чем** `k` дугам.

```text
D_0[s] = 0, у остальных D_0[v] = ∞
D_k[v] = min(D_(k-1)[v], min по дугам u→v (D_(k-1)[u] + w(u,v)))
```

Если в достижимой из `s` части нет отрицательных циклов, из оптимального маршрута можно удалить циклы, не увеличив его вес. Существует простой кратчайший путь, содержащий не более `n - 1` рёбер. Поэтому достаточно `D_(n-1)`.

Не путать «ровно `k`» и «не более `k`»: сохранение `D_(k-1)[v]` в формуле относится ко второму варианту. При вычислении слоя используем только предыдущий слой.

**Точка остановки:** постановка динамики и причина границы `n - 1` известны. Полное доказательство и реализация остаются на лекцию 7.

### Блок C — ещё 10 минут: Форд—Беллман и два способа обновления

Сначала показать буквальную реализацию динамики:

```text
d = [∞] * n
d[s] = 0
repeat n - 1 times:
    next = copy(d)
    for (u, v, w) in edges:
        if d[u] != ∞:
            next[v] = min(next[v], d[u] + w)
    d = next
```

После `k` проходов здесь строго `d[v] = D_k[v]`. Для практической версии можно релаксировать один массив на месте:

```text
repeat n - 1 times:
    changed = false
    for (u, v, w) in edges:
        if d[u] != ∞ and d[u] + w < d[v]:
            d[v] = d[u] + w
            changed = true
    if not changed:
        break
```

При обновлении на месте один проход может распространить улучшение через несколько дуг. Поэтому нельзя утверждать, что он учитывает только пути до `k` рёбер. Корректный инвариант: после `k` проходов `d[v] <= D_k[v]`, при этом всякая конечная оценка — длина некоторого маршрута. В отсутствие достижимых отрицательных циклов после `n - 1` проходов получаем истинные расстояния.

Для ручного примера взять цепочку `s → a (2)`, `a → b (-1)`, `b → t (3)`. При порядке дуг от `s` к `t` обновления на месте дадут все расстояния за один проход; при обратном порядке понадобится три. Два массива в обоих случаях продвигаются ровно по одному слою.

Версия на месте работает за `O(n + nm)` с учётом инициализации, обычно пишут `O(nm)`; дополнительная память `O(n)`. Буквальная версия с копированием всего массива на каждом слое требует `O(n(n + m))` времени и `O(n)` дополнительной памяти. Различие существенно при большом числе изолированных вершин.

**Точка остановки:** базовая динамика и обе реализации разобраны. На лекции 7 начать с проверки инвариантов, затем перейти к дополнительному проходу для поиска отрицательных циклов, их восстановлению и вершинам с ответом `-∞`.
