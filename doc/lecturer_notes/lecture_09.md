Обозначения: `n = |V|`, `m = |E|`. **Граф неориентированный**, веса могут быть отрицательными, нулевыми и равными. У каждого ребра свой `id`; параллельные рёбра различаем, петли никогда не входят в остов. В основной части граф связный и `n >= 1`; для несвязного отдельно обсуждаем минимальный остовный лес. Отрицательные веса здесь не создают проблемы неограниченного уменьшения: выбираем дерево из конечного набора рёбер, а не маршрут с повторениями.

## 1. Остов и минимальный остов

**Остовное дерево** связного графа — подграф на всех его вершинах, который связен и не содержит циклов. У него ровно `n - 1` рёбер. Любой DFS/BFS связного графа выделяет остов, но произвольный порядок обхода не минимизирует сумму весов.

**Минимальное остовное дерево (MST)** минимизирует сумму весов выбранных рёбер среди всех остовных деревьев. Это ограничение на дерево существенно: при отрицательных весах задача о произвольном связном подграфе — другая задача, поскольку добавление отрицательного ребра цикла может уменьшить его вес.

В несвязном графе остовного дерева нет. Можно построить **минимальный остовный лес (MSF)**: по минимальному дереву в каждой компоненте. При `c` компонентах лес содержит `n - c` рёбер. Для одной вершины остов пуст, его вес равен 0.

### Почему это не дерево кратчайших путей

Треугольник: `s—a` веса 2, `s—b` веса 2, `a—b` веса 1.

- Дерево кратчайших путей из `s` содержит оба ребра веса 2; его сумма равна 4.
- MST содержит `a—b` и одно из рёбер веса 2; его сумма равна 3.
- В MST путь из `s` до одной из вершин имеет длину 3, хотя в исходном графе расстояние равно 2.

Вопрос: «Что именно минимизируется?» Ответ: сумма весов всех рёбер дерева, а не каждый путь из выбранного корня.

### Пример A — один граф для Прима и Крускала

```text
AB: 1    AC: 4
BC: 2    BD: 5    BE: 6
CD: 1    CE: 3
DE: 2
```

Пять вершин, восемь рёбер. При равных весах для трассировок упорядочиваем ребро по буквам концов, затем сравниваем пары лексикографически. Это только способ сделать пример воспроизводимым; корректность не требует именно такого порядка.

Ожидаемый ответ: `{AB, BC, CD, DE}`, сумма `1 + 2 + 1 + 2 = 6`. Пока дать аудитории попробовать построить дешёвую сеть, затем обосновать выбор через разрезы.

## 2. Теорема о разрезе и безопасное ребро

**Разрез** — разбиение вершин на непустые части `S` и `V \ S`. Ребро пересекает разрез, если его концы лежат в разных частях. Это тот же термин, который позже появится в потоках, но сегодня нас интересует вес отдельного ребра разреза.

Пусть `F` — уже выбранные рёбра, и существует MST, содержащее всё `F`. Говорим, что разрез **не пересекает F**, если ни одно выбранное ребро не соединяет его разные стороны.

**Теорема о безопасном ребре.** Если разрез не пересекает `F`, а `e` — ребро минимального веса среди всех пересекающих его рёбер, то существует MST, содержащее `F ∪ {e}`.

Это нужная для алгоритмов усиленная формулировка: новые выборы должны быть совместимы со всеми предыдущими, а не просто по отдельности входить в какие-то оптимальные деревья.

### Доказательство обменом

1. Возьмём MST `T`, содержащее `F`. Если `e` уже в `T`, всё доказано.
2. Добавление `e` в дерево создаёт единственный цикл. Путь в `T` между концами `e` должен пересечь разрез, поэтому на этом цикле есть другое пересекающее ребро `f`.
3. `f` не принадлежит `F`, поскольку разрез не пересекает выбранные рёбра. По минимальности `e` имеем `w(e) <= w(f)`.
4. `T' = T + e - f` — снова остовное дерево. Оно содержит `F ∪ {e}` и имеет вес не больше веса `T`. Поскольку `T` оптимально, `T'` тоже MST.

Рисунок для доски: две области разреза, ребро `e` между ними и обходной путь дерева, который пересекает границу через `f`.

### Что меняется при равных весах

Минимальное ребро разреза входит **хотя бы в одно** MST. Оно не обязательно входит во все MST: в треугольнике из рёбер веса 1 можно выбрать любые два.

Если же ребро — **единственный** минимум данного разреза, оно входит в **каждое** MST: при его отсутствии обмен строго уменьшил бы вес дерева. В доказательстве общего случая нельзя заменять `<=` на `<`.

## 3. Алгоритм Прима

Выбираем стартовую вершину и выращиваем одно дерево. Пусть `S` — уже включённые вершины. На каждом шаге берём самое лёгкое ребро между `S` и оставшимися вершинами и добавляем его внешний конец.

Разрез `(S, V \ S)` не пересекает выбранные рёбра: они целиком внутри `S`. Теорема о безопасном ребре сохраняет инвариант «существует MST, содержащее всё выбранное». Новая вершина подключается одним ребром, поэтому цикл не появляется. В связном графе после `n - 1` добавлений получаем MST.

### Трассировка на примере A, старт A

| Добавляем вершину | Выбранное ребро | Сумма | Лучшие подключения оставшихся |
|---|---|---:|---|
| A | — | 0 | B:1 через A; C:4 через A; D,E:∞ |
| B | AB | 1 | C:2 через B; D:5 через B; E:6 через B |
| C | BC | 3 | D:1 через C; E:3 через C |
| D | CD | 4 | E:2 через D |
| E | DE | 6 | — |

Веса последовательно добавленных рёбер `1,2,1,2` не обязаны возрастать.

### Ключ Прима и расстояние Дейкстры

```text
Дейкстра: d[v] = min(d[v], d[u] + w(u,v))
Прим:     key[v] = min(key[v], w(u,v))
```

В Приме `key[v]` — вес **одного** лучшего ребра, соединяющего `v` с текущим деревом. Расстояние от старта не вычисляется. Поэтому отрицательные веса допустимы: доказательство через разрез не использует неотрицательность.

### Псевдокод с кучей и повторными записями

```text
inside = [false] * n
key = [∞] * n
parentEdge = [-1] * n
key[start] = 0
heap = min_heap([(0, start)])
answer = []
total = 0
count = 0

while heap is not empty:
    (k, v) = heap.pop_min()
    if inside[v] or k != key[v]:
        continue
    inside[v] = true
    count += 1
    if parentEdge[v] != -1:
        answer.push(parentEdge[v])
        total += k
    for (to, w, id) in adj[v]:
        if not inside[to] and w < key[to]:
            key[to] = w
            parentEdge[to] = id
            heap.push((w, to))

if count != n:
    report "Остовного дерева нет"
else:
    output(total, answer)
```

Этот код решает задачу для связного графа и обнаруживает несвязность. Для MSF запускаем новый старт в каждой ещё не включённой компоненте, со значением ключа 0; стартовые фиктивные подключения в ответ не добавляем. Петли отсекаются условием `not inside[to]`, параллельные рёбра корректно сравниваются по весам, их `id` различны.

### Сложность

- Линейный выбор минимума из массива: `O(n² + m)` при списках смежности, дополнительная память `O(n)`. Для простого графа обычно пишут `O(n²)`.
- При матрице смежности: `O(n²)` времени и памяти; удобно для плотных или неявно заданных полных графов.
- Приведённая куча с повторными записями: `O(n + m log(m + 2))` времени, `O(n + m)` дополнительной памяти. Возможны `O(m)` успешных улучшений и записей.
- Куча с уменьшением ключа: `O((n + m) log(n + 1))` времени, `O(n)` дополнительной памяти. Реализацию уменьшения ключа не разбираем.

Для простого связного графа оценки кучи обычно сокращают до `O(m log n)`. При произвольном числе параллельных рёбер не подменять `log m` на `log n` без оговорки.

## 4. DSU — система непересекающихся множеств

Крускал будет выращивать несколько компонент сразу. Нужны операции:

- `find(v)` — представитель компоненты;
- `unite(a,b)` — объединить разные компоненты и сообщить, произошло ли объединение.

В начале каждая вершина в отдельном множестве. DSU хранит лес родительских ссылок, корень множества — его представитель. **Это служебный лес, а не выбранные рёбра MST.** Для выдачи остова нужно отдельно сохранять `id` принятых рёбер.

```text
parent[v] = v для всех v
rank[v] = 0 для всех v

find(v):
    if parent[v] != v:
        parent[v] = find(parent[v])
    return parent[v]

unite(a, b):
    a = find(a)
    b = find(b)
    if a == b:
        return false
    if rank[a] < rank[b]:
        swap(a, b)
    parent[b] = a
    if rank[a] == rank[b]:
        rank[a] += 1
    return true
```

**Объединение по рангу:** корень меньшего ранга подвешиваем к большему; при равных рангах новый корень увеличивает ранг на 1. Без сжатия ранг совпадает с высотой, а корень ранга `r` представляет хотя бы `2^r` элементов. Поэтому высота не больше `log₂ n`.

**Сжатие пути:** при `find` все встреченные вершины перенаправляются прямо к корню. После сжатия ранг больше не обязан совпадать с текущей высотой; его не пересчитываем и не уменьшаем. Он остаётся верхней оценкой высоты.

Вариант вместо ранга: хранить размер множества и подвешивать меньшее к большему. Две эвристики объединения не нужно применять одновременно; код выше использует ранг.

Пример на доске: объединить `A,B`, затем `C,D`, затем две полученные компоненты. Если `C` подвесили к `A`, перед `find(D)` путь имеет вид `D → C → A`, после — `D → A`. Представитель определяется историей операций и не обязан быть минимальной вершиной компоненты.

С обеими эвристиками последовательность `q` операций после инициализации занимает `O(n + q α(n))` времени, где `α` — обратная функция Аккермана; память `O(n)`. Это **амортизированная**, а не гарантированная постоянная стоимость отдельного вызова. Доказательство этой оценки не входит в пару; вывод `O(log n)` без сжатия по удвоению размеров можно показать устно.

## 5. Алгоритм Крускала

Сортируем рёбра по неубыванию веса. Принимаем очередное ребро, только если его концы сейчас в разных компонентах выбранного леса. Это одновременно проверка, что добавление не создаст цикл.

```text
sort(edges by (weight, id))
initialize DSU(n)
answer = []
total = 0
components = n

for (u, v, w, id) in edges:
    if unite(u, v):
        answer.push(id)
        total += w
        components -= 1

if components == 1:
    output "MST", total, answer
else:
    output "MSF", total, answer, components
```

Код просматривает все рёбра и выдаёт лес для несвязного графа. Если требуется только MST и приняты `n - 1` рёбер, можно остановиться. Для `n = 1` ответ пустой и стоимость 0. Петли никогда не объединяют разные множества и пропускаются автоматически.

### Трассировка на примере A

| Ребро | Вес | Действие | Компоненты после шага |
|---|---:|---|---|
| AB | 1 | взять | AB, C, D, E |
| CD | 1 | взять | AB, CD, E |
| BC | 2 | взять | ABCD, E |
| DE | 2 | взять | ABCDE |
| CE | 3 | пропустить: цикл | ABCDE |
| AC | 4 | пропустить: цикл | ABCDE |
| BD | 5 | пропустить: цикл | ABCDE |
| BE | 6 | пропустить: цикл | ABCDE |

После `DE` уже можно остановиться. Последние строки показаны для понимания проверки DSU. Сумма совпадает с Примом: 6.

### Доказательство корректности

Инвариант: выбранный лес `F` содержится в некотором MST. В начале `F` пуст, условие выполнено.

Пусть принимаем ребро `e = (u,v)` между разными компонентами. Возьмём `S` равным текущей компоненте `u`. Разрез не пересекает `F`.

Почему `e` — минимум этого разреза? Любое ребро строго меньшего веса уже рассмотрено. Если бы такое ребро пересекало текущий разрез, то в момент рассмотрения его концы тоже были бы в разных компонентах: DSU только объединяет множества. Значит, оно было бы принято и соединило бы две стороны, противоречие. Равные веса безопасны по нестрогой версии теоремы.

Следовательно, `e` безопасно и сохраняет инвариант. Пропущенное ребро замыкало бы цикл, поэтому его не добавляем. Если исходный граф связен, после обработки рёбер все вершины окажутся в одной компоненте: иначе существовало бы соединяющее разные итоговые компоненты ребро, которое алгоритм обязан был принять. Получен остов, содержащийся в MST, значит он сам MST.

Для несвязного графа то же рассуждение применяется независимо внутри каждой компоненты и даёт MSF.

### Сложность

Инициализация DSU — `O(n)`, сортировка — `O(m log(m + 1))`, операции DSU — `O(m α(n))`. Итого:

```text
O(n + m log(m + 1) + m α(n)) времени
O(n) дополнительной памяти для DSU
```

Список рёбер и ответ занимают до `O(n + m)` памяти; дополнительная память сортировки зависит от реализации. Для простого связного графа обычно пишут `O(m log n)`. Кратные рёбра разрешены, поэтому в общем случае честнее сохранять сортировку через `log m`.

## 6. Сравнение и контрольные вопросы

| Ситуация | Удобный выбор |
|---|---|
| Уже дан список рёбер | Крускал + DSU |
| Разреженный граф в списках смежности | Прим с кучей или Крускал |
| Плотный граф или веса вычисляются по паре вершин | Прим с массивом за `O(n²)`; неявные веса не обязательно хранить матрицей |
| Нужно построить лес несвязного графа | Крускал сразу; Прим с перезапуском в каждой компоненте |

| Вопрос | Ответ |
|---|---|
| Почему недостаточно взять `n - 1` самых лёгких рёбер? | они могут содержать цикл и не соединить все вершины |
| Минимум разреза входит во все MST? | только если он единственный; при равенстве — хотя бы в одно |
| Может ли Прим работать с отрицательными весами? | да, обоснование через разрез не требует неотрицательности |
| Равные веса всегда означают несколько MST? | нет: граф, который сам является деревом, имеет единственный остов при любых весах |
| Можно ли выдать `parent` из DSU как остов? | нет, эти ссылки описывают служебное представление компонент |
| Как узнать, что Крускал построил дерево, а не лес? | одна компонента, или приняты `n - 1` рёбер при `n >= 1` |
| Почему разрез должен не пересекать F? | обмен обязан сохранить все ранее принятые рёбра |

Типичные ошибки: складывать в Приме `key[u] + w`, маркировать вершину включённой при добавлении в кучу, соединять в DSU произвольные вершины вместо корней, считать ранг точной высотой после сжатия, переполнять тип суммарной стоимости, терять идентификатор параллельного ребра.

## 7. Резерв на 5 / 10 / 20 минут

### Блок A — 5 минут: свойство цикла

**Единственное самое тяжёлое ребро цикла не входит ни в одно MST.** Если бы оно входило в дерево `T`, удаление разбило бы `T` на две части. Остальная часть исходного цикла содержит ребро, соединяющее эти части, и оно строго легче. Замена дала бы более дешёвое дерево — противоречие.

Уникальность максимума существенна: если все три ребра треугольника весят 1, каждое входит в какой-нибудь MST. При нестрогом максимуме можно утверждать лишь, что существует MST без выбранного максимального ребра.

Пример A: в цикле `A—B—C—A` ребро `AC` веса 4 — единственный максимум, поэтому в MST оно не нужно.

**Точка остановки:** умеем обосновать и принятие ребра через разрез, и исключение через цикл.

### Блок B — ещё 5 минут: единственность MST

Если все веса различны, MST единственно. Предположим, существуют разные MST `T1` и `T2`. Возьмём самое лёгкое ребро `e` их симметрической разности; пусть оно принадлежит `T1`. Удаление `e` разделяет `T1` на две части. Путь между концами `e` в `T2` содержит пересекающее этот разрез ребро `f`. Оно не принадлежит `T1`, значит входит в симметрическую разность, и `w(f) > w(e)`. Замена `f` на `e` в `T2` уменьшила бы вес — противоречие.

Обратное неверно. Например, путь из трёх вершин с обоими весами 1 — единственный остов своего графа. Не объявлять условие разных весов необходимым.

**Точка остановки:** разобрано достаточное условие единственности; отдельный алгоритм проверки единственности не вводим.

### Блок C — ещё 10 минут: идея Борувки

Переход: «Прим присоединял одну вершину к одному дереву, Крускал просматривал глобально отсортированные рёбра. Можно ли каждой текущей компоненте дать выбрать своё лучшее подключение?»

В начале каждая вершина — компонента. В одной фазе для каждой текущей компоненты находим самое лёгкое исходящее ребро. Затем пытаемся объединить компоненты через выбранные рёбра. Все минимумы фазы вычисляются до начала её объединений.

Для аккуратной обработки равных весов используем единый порядок `(weight, id)` при выборе минимумов. На шаге объединений снова проверяем `unite`: одно ребро могут выбрать обе компоненты, дубли добавлять нельзя. Единый порядок выбора устраняет циклы из различных выбранных рёбер: максимальное по этому порядку ребро предполагаемого цикла не могло быть минимумом ни для одной из его концевых компонент.

Каждое выбранное ребро — минимум разреза своей компоненты. Совместную безопасность можно понимать как применение теоремы о разрезе при едином разрешении равенств; полное обоснование и реализацию оставить на лекцию 10.

Пример A, первая фаза из одиночных вершин:

- `A` и `B` выбирают `AB`;
- `C` и `D` выбирают `CD`;
- `E` выбирает `DE`.

После объединений остаются `AB` и `CDE`. Во второй фазе обе выбирают `BC`; получаем тот же остов веса 6.

В связном графе каждая из более чем одной текущих компонент выбирает выход наружу; каждая новая компонента содержит минимум две старые. Поэтому число компонент за фазу как минимум вдвое уменьшается, фаз `O(log n)`. При реализации с явными метками компонент и линейной обработкой каждой фазы получают `O(m log n)` для связного графа. Если объединения реализованы обычной DSU, грубая оценка непосредственно из числа вызовов — `O(n + m log n · α(n))`; детали реализации и стандартную оценку разобрать на следующей паре.

**Точка остановки:** известны идея, один пример и уменьшение числа компонент. Полный алгоритм Борувки остаётся частью лекции 10; пройденное введение не повторять целиком.
