Обозначения как на лекции 6: `n = |V|`, `m = |E|`, `s` — источник, `w(u,v)` — вес дуги, `δ(s,v)` — истинное расстояние, `d[v]` — текущая оценка. Граф ориентированный; неориентированное ребро отрицательного веса само по себе даёт отрицательный цикл из двух дуг — сказать это вслух один раз. Если цель недостижима, `δ = +∞`; если стоимость маршрутов не ограничена снизу, `δ = -∞`. Перевзвешивание: `w_p(u,v) = w(u,v) + p(u) - p(v)`.

## 1. Где ломается Дейкстра — 5 минут

Пример B с лекции 6, **исходные веса**:

```text
s → a (2), s → b (5), b → a (-4), a → t (3), b → t (6)
```

Дейкстра после `s` зафиксирует `a` с оценкой 2, хотя `s → b → a` стоит 1. В доказательстве ломается ровно одно неравенство: «оставшийся участок пути не уменьшает длину». Разрешить повторные обработки — значит получить другой алгоритм, к которому старые доказательство и асимптотика не относятся.

Три разные ситуации, которые нужно различать:

- **отрицательная дуга** без отрицательных циклов — расстояния конечны (пример B — вообще DAG);
- **отрицательный цикл, достижимый из `s`**, из которого достижима `v` — `δ(s,v) = -∞`, ходим по циклу сколько угодно;
- **отрицательный цикл, недостижимый из `s`** или из которого `v` недостижима — на ответ для `v` не влияет.

## 2. Динамика по числу рёбер — 13 минут

Сначала разбираем динамику **по ровно `k` рёбрам** — она прямо выражает идею «последняя дуга + оптимальный префикс». Затем переходим к варианту «не более `k`», который и реализует Форд—Беллман.

### Ровно `k` рёбер

`D_k[v]` — минимальная стоимость маршрута из `s` в `v`, содержащего **ровно** `k` дуг (`∞`, если таких нет). Маршрут может повторять вершины и дуги.

```text
D_0[s] = 0, у остальных D_0[v] = ∞
D_k[v] = min по дугам u→v с D_(k-1)[u] != ∞ (D_(k-1)[u] + w(u,v))
```

Обоснование перехода: у маршрута ровно из `k >= 1` дуг есть последняя дуга `u → v`, а префикс — маршрут ровно из `k - 1` дуг в `u`; его можно заменить оптимальным, не ухудшив вес. Если в `v` не входит ни одна дуга из вершины с конечным `D_(k-1)`, то `D_k[v] = ∞`.

Хранение: матрица `D` размером `n × n` (строка — `k`, столбец — `v`); каждая строка считается из предыдущей за `O(n + m)`. Это и есть «хранение в матрице» из формулировки темы [3.4](../weighted_graph_shortest_paths/3.4.md).

**Важно:** `D_k[v]` **не монотонно** по `k`. Пример B с исходными весами (`n = 4`):

| k | s | a | b | t |
|---:|---:|---:|---:|---:|
| 0 | 0 | ∞ | ∞ | ∞ |
| 1 | ∞ | 2 | 5 | ∞ |
| 2 | ∞ | 1 | ∞ | 5 |
| 3 | ∞ | ∞ | ∞ | 4 |

У `a` значение падает с 2 до 1, а затем становится `∞`: маршрутов в `a` ровно из трёх дуг нет. Поэтому ответ — **минимум по всем строкам**:

```text
δ(s,v) = min по k = 0..n-1 от D_k[v]
```

Для примера B: `a = min(2, 1) = 1`, `b = 5`, `t = min(5, 4) = 4` — совпадает с лекцией 6. Граница `n - 1` обоснована ниже.

Стоимость: `O(n(n + m))` времени, `O(n²)` памяти на всю матрицу. Память сокращается до `O(n)`: хранить две строки и текущий минимум по столбцам.

### Не более `k` рёбер

Чтобы не искать минимум по строкам в конце, переходим к префиксному минимуму:

```text
M_k[v] = min по j = 0..k от D_j[v]   — маршруты из НЕ БОЛЕЕ k дуг
M_0 = D_0
M_k[v] = min(M_(k-1)[v], min по дугам u→v с M_(k-1)[u] != ∞ (M_(k-1)[u] + w(u,v)))
```

Обоснование: маршрут из не более `k` дуг либо короче `k` дуг (первое слагаемое), либо ровно из `k` — тогда последняя дуга `u → v` и префикс из не более `k - 1` дуг. Равносильно: добавить в каждую вершину петлю веса 0 и считать «ровно `k`».

`M_k` монотонно не возрастает по `k`, а ответ — просто последняя строка `M_(n-1)`. Для примера B: `M_3 = [0, 1, 5, 4]`. Именно эту динамику реализует Форд—Беллман.

**Лемма о границе `n - 1`.** Если в `v` нет маршрута сколь угодно малой стоимости (т.е. `δ(s,v)` конечно), то `δ(s,v) = M_(n-1)[v] = min по k = 0..n-1 от D_k[v]`.

Доказательство: если `δ(s,v)` конечно, ни один цикл на маршрутах из `s` в `v` не отрицателен — иначе по нему можно ходить бесконечно. Удаляя из маршрута циклы, вес не увеличиваем; получаем простой путь, в нём не более `n - 1` дуг. Значит, минимум по всем маршрутам достигается среди маршрутов из не более `n - 1` дуг.

Вопрос аудитории: «Почему нельзя взять просто `D_(n-1)[v]`?» Ответ: кратчайший путь может иметь меньше `n - 1` дуг, а маршрута ровно из `n - 1` дуг может не быть вовсе (в примере B `D_3[a] = ∞`).

## 3. Форд—Беллман — 14 минут

### Буквальная реализация: два массива

```text
d = [∞] * n
d[s] = 0
repeat n - 1 times:
    next = copy(d)
    for (u, v, w) in edges:
        if d[u] != ∞ and d[u] + w < next[v]:
            next[v] = d[u] + w
    d = next
```

После `k` проходов `d = M_k` — прямое следствие формулы для «не более `k`». Время `O(n(n + m))` из-за копирования, память `O(n)` сверх графа.

### Практическая реализация: релаксация на месте

```text
d = [∞] * n
parent = [-1] * n
d[s] = 0
repeat n - 1 times:
    changed = false
    for (u, v, w) in edges:
        if d[u] != ∞ and d[u] + w < d[v]:
            d[v] = d[u] + w
            parent[v] = u
            changed = true
    if not changed:
        break
```

**Инвариант:** после `k` проходов для каждой вершины

```text
M_k[v] >= d[v] >= δ(s,v)
```

- Правое неравенство: любая конечная оценка — вес некоторого маршрута из `s` в `v` (индукция по числу релаксаций).
- Левое — индукция по `k`. База `k = 0` очевидна. Шаг: оценки только уменьшаются, поэтому `d[v] <= M_(k-1)[v]` сохраняется. Для дуги `u → v` в момент её релаксации на `k`-м проходе уже `d[u] <= M_(k-1)[u]`, и после неё `d[v] <= M_(k-1)[u] + w(u,v)`. Берём минимум — получаем `d[v] <= M_k[v]`.

**Следствие:** если отрицательных циклов, достижимых из `s`, нет, то после `n - 1` проходов `M_(n-1)[v] = δ(s,v)` и `d[v] = δ(s,v)` для всех `v`.

**Ранний выход:** если проход ничего не изменил, следующие проходы тоже ничего не изменят — состояние то же. Значит, отрицательного цикла, достижимого из `s`, нет (см. раздел 5: иначе изменения были бы на любом проходе).

Нельзя говорить, что после `k` проходов на месте учтены пути **ровно** из `k` рёбер: один проход может протащить улучшение через несколько дуг. Пример на доске — цепочка `s → a (2)`, `a → b (-1)`, `b → t (3)`: в порядке дуг от `s` хватает одного прохода с изменениями, в обратном нужно три.

**Асимптотика:** `O(nm)` времени (честнее `O(n + nm)` с инициализацией), `O(n)` дополнительной памяти. Порядок дуг влияет на число реальных проходов, но не на худший случай.

## 4. Восстановление пути — 5 минут

Как в Дейкстре: при строгом улучшении запоминаем `parent[v]` (и `parentEdge[v]` для параллельных дуг), затем идём от `t` к `s` и разворачиваем.

Отличие от Дейкстры: **пока есть отрицательный цикл, граф предков может содержать цикл**, и наивный проход `while v != -1` зависнет. Восстанавливать путь только до вершин с конечным `δ`, после проверки отрицательных циклов и поиска вершин с `-∞` (разделы 5–6). Если цикла нет, у вершин с конечным расстоянием цепочка предков — простой кратчайший путь.

Проверка `d[u] != ∞` в релаксации обязательна: иначе `INF + (-5) < INF` создаст «маршрут» в недостижимую вершину. В коде `INF` и тип выбирать так, чтобы `d[u] + w` не переполнялся; при отрицательных циклах оценки уменьшаются линейно по числу проходов — `long long` и проверка на `-INF` при больших весах.

## 5. Отрицательный цикл: обнаружение и восстановление — 13 минут

### Обнаружение: `n`-й проход

После `n - 1` проходов делаем ещё один. **Если хотя бы одна оценка улучшилась — из `s` достижим отрицательный цикл; если нет — не достижим.**

Доказательство «если цикл есть, улучшение будет». Пусть `C = v_0 → v_1 → … → v_k = v_0` достижим из `s`, значит все `d[v_i]` конечны. Пусть за `n`-й проход ни одна вершина цикла не изменилась. Тогда значения `d` на `C` весь проход постоянны, каждая дуга цикла проверялась с этими значениями и не сработала, поэтому `d[v_i] <= d[v_(i-1)] + w(v_(i-1), v_i)` для всех `i` одновременно. Сложим по циклу: левые и правые суммы `d` совпадают, остаётся `0 <= w(C)`. Противоречие с `w(C) < 0`.

Доказательство «если улучшение было, цикл есть». Следствие раздела 3 здесь неприменимо — оно предполагает отсутствие отрицательных циклов, достижимых из `s`, — поэтому опираемся на лемму и инвариант. Пусть на `n`-м проходе улучшилась `d[x]` через дугу `u → x`. Если бы `δ(s,x)` было конечно, то по лемме о границе `n - 1` (раздел 2) `M_(n-1)[x] = δ(s,x)`, а по инварианту раздела 3 `δ(s,x) <= d[x] <= M_(n-1)[x]`, т.е. уже `d[x] = δ(s,x)`. Но `d[u] + w(u,x)` — вес некоторого маршрута в `x`, меньший `d[x] = δ(s,x)`. Противоречие, значит `δ(s,x) = -∞`, а это возможно только при достижимом отрицательном цикле.

Для версии с двумя массивами аргумент ещё короче: `M_n[x] < M_(n-1)[x]` (т.е. `D_n[x] < M_(n-1)[x]`) означает, что лучший маршрут в `x` имеет ровно `n` дуг, т.е. содержит цикл; если бы цикл был неотрицательным, его удаление дало бы маршрут из меньшего числа дуг не хуже.

### Восстановление цикла

```text
x = последняя вершина, улучшенная на n-м проходе
repeat n times:
    x = parent[x]           # теперь x гарантированно лежит на цикле предков
cycle = [x]
v = parent[x]
while v != x:
    cycle.push(v)
    v = parent[v]
cycle.reverse()             # цикл в порядке дуг
```

Почему `n` шагов: цепочка предков из улучшенной вершины не обрывается на `parent = -1`, а уходит в цикл (он может проходить и через `s`, если `s` лежит на отрицательном цикле); «хвост» до цикла короче `n`. Этот факт даём **без строгого доказательства**, в коде на него опираемся.

**Доказываем строго другое: любой цикл в графе предков отрицателен.** Пусть цикл замыкается в момент, когда ставим `parent[v] = u`. Для каждой другой дуги цикла `u_i → v_i` с `parent[v_i] = u_i` в момент установки было `d[v_i] = d[u_i] + w_i`; после этого `d[u_i]` могло только уменьшиться. `d[v_i]` могло измениться лишь при новой релаксации: через другую вершину — тогда сменился бы предок, через ту же `u_i` — тогда снова `d[v_i] = d[u_i] + w_i`. Значит, всё время `d[v_i] >= d[u_i] + w_i`. Для замыкающей дуги — строго: `d[v] > d[u] + w(u,v)` до обновления. Суммируя по циклу, получаем `0 > w(C)`.

## 6. Вершины с ответом `-∞` — 7 минут

**Утверждение.** `δ(s,v) = -∞` тогда и только тогда, когда `v` достижима из какой-либо вершины, улучшенной на `n`-м проходе.

- Улучшенная вершина `x` имеет `δ(s,x) = -∞` (раздел 5), а `-∞` распространяется по дугам на всё достижимое.
- Если `δ(s,v) = -∞`, то `v` достижима из отрицательного цикла, достижимого из `s`. На этом цикле в `n`-м проходе улучшается хотя бы одна вершина (раздел 5), а из неё достижим весь цикл и `v`.

Алгоритм: `n - 1` проходов, ещё один проход с пометкой улучшенных вершин, затем BFS/DFS из всех помеченных. Помеченным и достижимым из них — `-∞`; у остальных достижимых из `s` `d[v] = δ(s,v)`; недостижимым — `+∞`. Время остаётся `O(nm)`.

Встречающаяся альтернатива — ещё `n` проходов, в которых `-∞` присваивается при любом улучшении и распространяется по дугам. Тоже корректно, но вдвое дороже и труднее обосновать.

### Пример C — трассировка на доске

```text
s → a (1), a → b (1), b → a (-3), b → t (2), s → c (2), c → t (5)
```

Цикл `a → b → a` весом `-2`, из него достижима `t`; вершина `c` до цикла не достаёт. Порядок дуг — как записаны, `n = 5`.

| После прохода | d[a] | d[b] | d[c] | d[t] |
|---|---:|---:|---:|---:|
| 1 | -1 | 2 | 2 | 4 |
| 2 | -3 | 0 | 2 | 2 |
| 3 | -5 | -2 | 2 | 0 |
| 4 | -7 | -4 | 2 | -2 |
| 5 (проверочный) | -9 | -6 | 2 | -4 |

В пятом проходе улучшились `b`, `a`, `t`; ответ `-∞` для `{a, b, t}`, `δ(s,c) = 2`. Последней улучшилась `t`; пять шагов по предкам `t → b → a → b → a → b` приводят на цикл, восстанавливаем `a → b → a`.

Вопрос аудитории: «Значение `d[c] = 2` правильное, а `d[t] = -4` — нет. Почему?» Потому что `t` достижима из цикла, а `c` — нет.

## 7. Флойд—Уоршелл — 16 минут

Задача всех пар. `dist_k[i][j]` — минимальный вес пути `i → j`, все **промежуточные** вершины которого из `{1, …, k}`.

```text
dist_0[i][i] = min(0, min вес петли i → i)
dist_0[i][j] = min вес дуги i → j  (∞, если дуги нет)
dist_k[i][j] = min(dist_(k-1)[i][j], dist_(k-1)[i][k] + dist_(k-1)[k][j])
```

Идея корректности: кратчайший простой путь с промежуточными из `{1..k}` либо не проходит через `k`, либо проходит ровно один раз — тогда делится на две части, промежуточные вершины которых из `{1..k-1}`. Без отрицательных циклов простых путей достаточно.

```text
for k in 1..n:
    for i in 1..n:
        if dist[i][k] == ∞: continue
        for j in 1..n:
            if dist[k][j] != ∞ and dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
                next[i][j] = next[i][k]
```

**Почему можно в одной матрице:** на фазе `k` строка и столбец `k` не меняются — `dist[i][k] + dist[k][k]` не меньше `dist[i][k]`, пока `dist[k][k] >= 0`. Если `dist[k][k] < 0`, цикл уже найден и точные значения не важны.

**Подводные камни:** инициализировать диагональ как `min(0, вес петли)` и брать минимум из параллельных дуг; если диагональ просто обнулить, отрицательная петля `i → i` потеряется и цикл не обнаружится. Порядок циклов: `k` — **внешний**; перепутанный порядок даёт неверный ответ. Проверки на `∞` нужны, чтобы `∞ + (отрицательное)` не стало «путём».

**Восстановление пути:** `next[i][j]` — первая вершина после `i` на пути. Инициализация `next[i][j] = j` для дуги, при улучшении `next[i][j] = next[i][k]`. Путь: `i, next[i][j], next[next[i][j]][j], …` до `j`. Как и в Форде—Беллмане, восстанавливать только пары с конечным ответом, не помеченные `-∞` (ниже): иначе проход по `next` может зациклиться.

**Отрицательные циклы:** после алгоритма отрицательный цикл есть тогда и только тогда, когда `dist[v][v] < 0` для некоторой `v`. Пара `(i, j)` получает `-∞`, если существует `k` с `dist[k][k] < 0`, `dist[i][k] < ∞`, `dist[k][j] < ∞`. Это дополнительный `O(n³)`. При отрицательных циклах значения могут убывать экспоненциально по числу фаз — в коде ограничивать снизу `-INF`.

Асимптотика: `O(n³)` времени, `O(n²)` памяти (ещё `O(n²)` на `next`).

### Пример D — трассировка (вершины 1..3)

```text
1 → 2 (4), 1 → 3 (3), 2 → 3 (-2), 3 → 1 (1)
```

| Фаза | Изменения |
|---|---|
| начальная | `dist[1] = [0, 4, 3]`, `dist[2] = [∞, 0, -2]`, `dist[3] = [1, ∞, 0]` |
| k = 1 | `dist[3][2] = 1 + 4 = 5`, `next[3][2] = next[3][1] = 1` |
| k = 2 | `dist[1][3] = 4 + (-2) = 2`, `next[1][3] = 2` |
| k = 3 | `dist[2][1] = -2 + 1 = -1`, `next[2][1] = next[2][3] = 3` |

Итог: `dist[1] = [0, 4, 2]`, `dist[2] = [-1, 0, -2]`, `dist[3] = [1, 5, 0]`. Путь `1 → 3`: `1 → 2 → 3`. Диагональ нулевая — отрицательных циклов нет (цикл `1 → 2 → 3 → 1` весит 3).

## 8. Алгоритм Джонсона — 10 минут

Задача всех пар в **разреженном** графе с отрицательными дугами. Идея: найти потенциал, делающий веса неотрицательными, и `n` раз запустить Дейкстру.

1. Добавить вершину `q` и дуги `q → v` веса 0 для всех `v`.
2. Форд—Беллман из `q`. В графе теперь `n + 1` вершина, поэтому нужно `n` проходов и проверочный `n + 1`-й — не переиспользовать границу `n - 1` для исходного графа. Если найден отрицательный цикл — сообщить и остановиться. Из `q` достижим любой цикл, поэтому проверка полная.
3. `h(v) = δ(q,v)` — конечно и `<= 0`.
4. Перевзвесить: `w_h(u,v) = w(u,v) + h(u) - h(v)` — это формула лекции 6 с потенциалом `p = h`.
5. Из каждой `u` запустить Дейкстру по `w_h`, вернуть `δ(u,v) = δ_h(u,v) - h(u) + h(v)`.

**Неотрицательность:** неравенство треугольника для расстояний от `q` даёт `h(v) <= h(u) + w(u,v)`, т.е. ровно `w_h(u,v) >= 0`. Сохранение кратчайших путей доказано на лекции 6 телескопической суммой — не повторяем.

**Связь с прошлой лекцией:** для примера B

```text
h(s) = 0, h(b) = 0, h(a) = min(0, 0 - 4, 2) = -4, h(t) = min(0, -4 + 3, 6) = -1
```

Это ровно потенциал, «данный готовым» на лекции 6. Сказать вслух: «вот откуда он брался».

Знак: потенциал — расстояние **от** фиктивного источника; в A* было `p = -h`, где `h` — оценка расстояния **до** цели. Обе формулы — частные случаи `w + p(u) - p(v)`.

**Асимптотика:** Форд—Беллман на `n + 1` вершине и `m + n` дугах — `O(n(n + m))`, плюс `n` запусков Дейкстры с кучей — `O(n(n + m) log n)`, при `m >= n` пишут `O(nm log n)`. С фибоначчиевой кучей `O(n(n + m) + n² log n)` = `O(nm + n² log n)` — упомянуть без доказательства. Память `O(n + m)` сверх ответа.

## 9. Оценки сложности и сравнение — 7 минут

Сводная таблица всех алгоритмов поиска кратчайших путей курса, включая Дейкстру с лекции 6. Память — дополнительная, сверх хранения графа (списки смежности `O(n + m)`, матрица `O(n²)`). На доске оставить столбцы «Алгоритм» и «Время»; откуда берётся каждая оценка — проговорить одной фразой.

| Алгоритм | Время | Доп. память | Откуда оценка |
|---|---|---|---|
| BFS, веса 1 (лекция 1) | `O(n + m)` | `O(n)` | каждая вершина в очереди один раз, каждая дуга просмотрена один раз |
| Релаксация в порядке топсорта, DAG (резерв A) | `O(n + m)` | `O(n)` | топсорт `O(n + m)` и один проход по дугам |
| Дейкстра, выбор минимума массивом | `O(n² + m)`; для простого графа `O(n²)` | `O(n)` | `n` раз ищем минимум за `O(n)`, каждая дуга релаксируется один раз; при множестве параллельных дуг слагаемое `m` может доминировать |
| Дейкстра, бинарная куча с уменьшением ключа | `O((n + m) log n)` | `O(n)` | `n` извлечений и до `m` уменьшений ключа, каждое `O(log n)` |
| Дейкстра, куча с повторными записями (код лекции 6) | `O(n + m log m)` | `O(n + m)` | до `m` вставок, в куче до `m` записей; для простого графа `log m <= 2 log n`, т.е. `O(m log n)` |
| Дейкстра, фибоначчиева куча | `O(m + n log n)` | `O(n)` | уменьшение ключа за `O(1)` амортизированно, извлечение `O(log n)`; без доказательства |
| Форд—Беллман | `O(nm)` | `O(n)` | `n - 1` проходов по `m` дугам, проверочный проход ещё `O(m)` |
| Форд—Беллман + поиск `-∞` | `O(nm)` | `O(n)` | к проходам добавляется один обход `O(n + m)` |
| Флойд—Уоршелл | `O(n³)` | `O(n²)` | `n` фаз по `n²` пар; `next` — ещё `O(n²)` |
| `n` × Дейкстра (куча), `w >= 0` | `O(n(n + m) log n)` | `O(n + m)` + ответ `O(n²)` | `n` независимых запусков |
| `n` × Дейкстра (массив), `w >= 0` | `O(n³)` | `O(n)` + ответ `O(n²)` | `n` запусков по `O(n²)` — как Флойд, но только без отрицательных дуг |
| Джонсон (куча) | `O(n(n + m) log n)` = `O(nm log n)` при `m >= n` | `O(n + m)` + ответ `O(n²)` | Форд—Беллман на `n + 1` вершине и `m + n` дугах, перевзвешивание `O(m)`, `n` Дейкстр |
| Джонсон (фибоначчиева куча) | `O(nm + n² log n)` | `O(n + m)` + ответ `O(n²)` | то же с Дейкстрой `O(m + n log n)`; без доказательства |

Что подчеркнуть для Дейкстры:

- Множитель `log` возникает только из очереди с приоритетом; сам перебор дуг всегда `O(m)`.
- Массив выгоднее кучи, когда `m log n > n²`, т.е. на плотных графах (`m ~ n²`). На разреженных (`m ~ n`) куча: `O(n log n)` против `O(n²)`.
- `O((n + m) log n)` — для связной части пишут `O(m log n)`; слагаемое `n` важно, только если много изолированных вершин.
- Прибавление константы ко всем весам не помогает: прибавка зависит от числа дуг пути. Повторные обработки вершин дают корректный ответ при отсутствии отрицательных циклов, но это уже другой алгоритм без оценки Дейкстры — в худшем случае экспоненциальное время. Отрицательные дуги с сохранением асимптотики Дейкстры — через потенциалы (Джонсон).

Ориентир на числах (считаем `log₂ 10⁴ ≈ 13`, `log₂ 500 ≈ 9`, порядок `10⁸` простых операций в секунду):

| Граф | Дейкстра: куча / массив | Форд—Беллман | Все пары: Флойд / Джонсон |
|---|---|---|---|
| разреженный, `n = 10⁴`, `m = 10⁵` | `~1.5·10⁶` / `10⁸` | `10⁹` | `10¹²` / `~1.5·10¹⁰` |
| плотный, `n = 500`, `m = 2.5·10⁵` | `~2.3·10⁶` / `2.5·10⁵` | `~1.3·10⁸` | `~1.3·10⁸` / `~1.3·10⁹` |

Выводы для доски: на разреженном графе — куча и Джонсон; на плотном — массив и Флойд. Форд—Беллман — только когда без отрицательных дуг не обойтись.

| Задача | Выбор |
|---|---|
| один источник, `w >= 0` | Дейкстра: куча на разреженном, массив на плотном |
| один источник, отрицательные дуги | Форд—Беллман; заодно находит `-∞` / цикл |
| один источник, DAG | релаксация в порядке топсорта |
| все пары, плотный граф или `n` до ~500 | Флойд—Уоршелл |
| все пары, разреженный граф | `n` × Дейкстра, при отрицательных дугах — Джонсон |

Итоговые фразы: Дейкстра фиксирует вершины, Форд—Беллман повторяет релаксации нужное число раз, Флойд расширяет множество промежуточных вершин, Джонсон убирает отрицательные веса потенциалом и сводит задачу к Дейкстре.

## 10. Контрольные вопросы

| Вопрос | Ответ |
|---|---|
| Почему достаточно `n - 1` проходов? | без отрицательных циклов есть простой кратчайший путь, в нём не более `n - 1` дуг |
| Верно ли, что после `k` проходов на месте `d[v] = M_k[v]`? | нет, только `d[v] <= M_k[v]` |
| Чем `D_k` отличается от `M_k`? | `D_k` — ровно `k` дуг, не монотонно; `M_k` — не более `k`, префиксный минимум `D_0..D_k` |
| Что означает улучшение на `n`-м проходе? | из `s` достижим отрицательный цикл, у улучшенной вершины `δ = -∞` |
| Все ли вершины с `-∞` улучшаются на `n`-м проходе? | нет, нужен обход из улучшенных |
| Почему нельзя восстанавливать путь до `-∞`-вершины по предкам? | цепочка предков может зациклиться |
| Зачем в Флойде `k` — внешний цикл? | динамика по множеству промежуточных вершин |
| Как Флойд обнаруживает отрицательный цикл? | `dist[v][v] < 0` |
| Почему в Джонсоне `w + h(u) - h(v) >= 0`? | неравенство треугольника для расстояний от `q` |
| Неориентированное ребро веса `-1` — что будет? | отрицательный цикл из двух дуг |

## 11. Резерв на 5 / 10 / 20 минут

### Блок A — 5 минут: кратчайшие пути в DAG

Если граф ацикличен, достаточно одного прохода релаксации в порядке топологической сортировки (лекция 2): к моменту обработки `u` все дуги, входящие в `u`, уже отрелаксированы. Время `O(n + m)`, отрицательные веса разрешены. Пример B — DAG: порядок `s, b, a, t`. Самый длинный путь в DAG — тот же алгоритм с заменой `w` на `-w` (в общем графе так нельзя: задача NP-трудна).

**Точка остановки:** связь с топологической сортировкой и оценка `O(n + m)`.

### Блок B — ещё 5 минут: очередь вместо полных проходов (SPFA)

Релаксировать дуги только из вершин, чья оценка изменилась: очередь «изменённых» вершин. На случайных графах часто быстро, но **худший случай остаётся `O(nm)`**, и существуют специально построенные тесты. Отрицательный цикл: вершина попала в очередь `n` раз (или длина пути по предкам достигла `n`). Сказать прямо: асимптотически это не улучшение.

**Точка остановки:** идея и честная оценка худшего случая.

### Блок C — ещё 10 минут: другие полукольца во Флойде

Та же схема `dist[i][j] = op(dist[i][j], comb(dist[i][k], dist[k][j]))`:

- транзитивное замыкание: `reach[i][j] |= reach[i][k] & reach[k][j]`, можно ускорить битсетами до `O(n³ / 64)`;
- путь с максимальной пропускной способностью (maximin): `max(min(...))`;
- путь с наименьшей максимальной дугой (minimax): `min(max(...))`.

Подводка к следующей теме: в **неориентированном** графе maximin-путь можно взять в максимальном остовном дереве, minimax-путь — в минимальном; это лекция 8. Для ориентированных графов это неверно.

**Точка остановки:** общая схема динамики и транзитивное замыкание.
