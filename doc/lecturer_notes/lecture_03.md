## Откуда начинаем

Вторая лекция пройдена целиком: деревья обхода, `tin/tout`, лемма о белых путях и топологическая сортировка уже известны. Обратные рёбра DFS кратко обсуждали. Достаточно восстановить их смысл на рисунке; заново доказывать свойства времён обхода не требуется.

Фраза для начала: «В прошлый раз времена выхода помогли упорядочить вершины графа без циклов. Сегодня научимся сжимать циклы в компоненты, а затем искать рёбра и вершины, от которых зависит связность».

Обозначения: `n = |V|`, `m = |E|`, граф хранится списками смежности. Каждый алгоритм запускает собственный DFS со свежими массивами. Для `tin` достаточно увеличивать таймер только при входе; для Косарайю достаточно списка выходов без числовых `tout`.

## 1. Короткое повторение: обратные рёбра

Нарисовать треугольник `0—1—2—0`; DFS идёт `0 → 1 → 2`. Рёбра `0—1` и `1—2` — древесные, ребро `2—0` даёт возврат к предку.

- Древесное ребро впервые открывает вершину.
- Обратное ребро направлено из потомка к предку в дереве DFS.
- В неориентированном графе каждое недревесное ребро между различными вершинами соединяет предка и потомка. Поперечных рёбер между разными ветвями DFS нет: первая обработанная ветвь обнаружила бы вторую через такое ребро.
- Одно неориентированное ребро хранится в двух списках. Запись древесного ребра со стороны ребёнка не считается отдельным обратным ребром; пропускаем именно идентификатор ребра прихода.
- В орграфе возможны также прямые и поперечные рёбра. Свойства неориентированного дерева DFS нельзя переносить на него автоматически.

Вопрос: «Если между родителем и ребёнком два параллельных ребра, можно ли пропустить оба?» Ответ: нет, второе ребро даёт обход первого. Петля не может быть мостом.

## 2. Слабая и сильная связность

**Слабая компонента** орграфа — компонента связности после снятия направлений с рёбер. Находим обычным DFS/BFS по неориентированной версии графа.

**Компонента сильной связности (SCC)** — максимальное множество взаимно достижимых вершин. Отношение «`u` достижима из `v` и `v` достижима из `u`» рефлексивно, симметрично и транзитивно, поэтому SCC разбивают вершины на непересекающиеся классы. Одиночная вершина тоже может быть SCC.

Один обычный DFS орграфа не выделяет SCC: в графе `a → b` он посетит обе вершины, но обратного пути нет.

### Пример A: один граф для SCC

Вершины `0, 1, 2, 3, 4, 5, 6`. Дуги:

```text
0 → 1, 1 → 2, 2 → 0,
2 → 3,
3 → 4, 4 → 3,
4 → 5.
6 — изолированная вершина.
```

Перебирать старты и соседей по возрастанию номеров.

- Слабые компоненты: `{0,1,2,3,4,5}` и `{6}`.
- SCC: `A = {0,1,2}`, `B = {3,4}`, `C = {5}`, `D = {6}`.
- Конденсация: `A → B → C`, отдельно `D`.

### Почему конденсация ациклична

Сжимаем каждую SCC в одну вершину, сохраняем дуги между разными компонентами, внутренние дуги убираем. Если бы в конденсации был ориентированный цикл, все компоненты на нём были бы взаимно достижимы и составляли бы одну SCC. Это противоречит их максимальности.

Переход: «Топологически упорядочить исходные вершины мешают циклы. Компоненты уже можно упорядочить. Как получить этот порядок, ещё не зная самих компонент?»

## 3. Алгоритм Косарайю

### Алгоритм и псевдокод

1. Полный DFS по исходному графу `G`; при выходе добавлять вершину в `order`.
2. Построить `GT`, развернув каждую дугу.
3. Просмотреть `order` с конца. Из каждой ещё не назначенной вершины запустить DFS по `GT`; посещённые этим запуском вершины получают один номер SCC.

```text
visited = [false] * n
order = []
comp = [-1] * n

dfs1(v):
    visited[v] = true
    for to in G[v]:
        if not visited[to]:
            dfs1(to)
    order.push(v)

dfs2(v, id):
    comp[v] = id
    for to in GT[v]:
        if comp[to] == -1:
            dfs2(to, id)

for v in vertices:
    if not visited[v]:
        dfs1(v)

id = 0
for v in reversed(order):
    if comp[v] == -1:
        dfs2(v, id)
        id += 1
```

В примере A список выходов: `[5,4,3,2,1,0,6]`. Старты второго прохода: `6`, `0`, `3`, `5`; уже назначенные вершины пропускаются. Получаем `{6}`, `{0,1,2}`, `{3,4}`, `{5}`.

### Доказательство через времена выхода компонент

Обозначим `T(C) = max(tout[v])` по вершинам компоненты `C`. Для любой дуги конденсации `C → D` верно **`T(C) > T(D)`**.

Рассмотреть два случая по первой обнаруженной вершине из `C ∪ D`:

1. Первой открыта вершина `c` из `C`. Все вершины `C` и `D` ещё белые и достижимы из `c` по белым путям внутри этих компонент и через дугу `C → D`. По лемме о белых путях они попадут в поддерево `c` и завершатся до неё. Значит, `T(C) > T(D)`.
2. Первой открыта вершина из `D`. Из `D` нельзя достичь `C`, иначе это одна SCC. Этот вызов соберёт всю `D` и завершится до обнаружения любой вершины `C`. Снова `T(C) > T(D)`.

Теперь берём ещё не выделенную компоненту с максимальным `T`. В неё нет дуг из других оставшихся компонент в `G`, иначе у предшественника было бы большее `T`. Следовательно, в `GT` из неё нет дуг в другие оставшиеся компоненты.

Второй DFS не покинет эту SCC среди неназначенных вершин, но посетит её целиком: разворот дуг сохраняет сильную связность. Удаляем выделенную компоненту из рассмотрения и повторяем рассуждение.

Подчеркнуть: убывание времён относится к **максимумам по компонентам**. Не нужно утверждать, что все времена одной SCC больше всех времён следующей.

### Сложность и построение конденсации

Два обхода и разворот дуг занимают `O(n + m)`. Дополнительная память — `O(n + m)`, включая `GT`; массивы и стек DFS занимают `O(n)`.

После нахождения `comp` перебираем исходные дуги `u → v` и добавляем `comp[u] → comp[v]`, если номера различны. За `O(n + m)` получаем конденсацию, возможно с повторными дугами; для ацикличности они не мешают. Если нужны уникальные дуги, стоимость их удаления учитывать отдельно.

## 4. Тарьян для SCC: один DFS и стек

Дать алгоритм и смысл условий без полного доказательства. Здесь `lowScc` — служебная метка Тарьяна; далее для неориентированного графа будем использовать отдельную метку `low`.

- `index[v]` — номер открытия вершины.
- `S` — стек открытых вершин, ещё не отнесённых к готовой SCC.
- `onStack[v]` — принадлежность именно этому стеку.
- `lowScc[v]` начинается с `index[v]`, получает `lowScc` детей DFS и `index` уже открытых соседей, которые остаются в `S`.

```text
timer = 0
index = [-1] * n
lowScc = [-1] * n
onStack = [false] * n
S = []

tarjan(v):
    index[v] = lowScc[v] = timer++
    S.push(v)
    onStack[v] = true
    for to in G[v]:
        if index[to] == -1:
            tarjan(to)
            lowScc[v] = min(lowScc[v], lowScc[to])
        else if onStack[to]:
            lowScc[v] = min(lowScc[v], index[to])

    if lowScc[v] == index[v]:
        component = []
        repeat:
            u = S.pop()
            onStack[u] = false
            component.push(u)
        until u == v
        output(component)

for v in vertices:
    if index[v] == -1:
        tarjan(v)
```

Интуиция: если метка стала меньше `index[v]`, закрывать компоненту на `v` рано — она связана с более ранней незакрытой частью обхода. Равенство выделяет корень SCC; её вершины лежат на вершине `S` вплоть до `v` включительно.

В примере A компоненты снимаются в порядке `{5}`, `{4,3}`, `{2,1,0}`, `{6}`. Дуга `4 → 5` не объединяет компоненты: это ребро дерева, и `lowScc[4]` берёт `min` с `lowScc[5] = 5`, но `5 > lowScc[4] = 3`, поэтому метка `4` не уменьшается. Проверка `onStack` относится только к уже посещённым соседям, не к рёбрам дерева.

**Стек SCC не совпадает со стеком рекурсии.** Мини-пример: `0 → 1`, `1 → 0`, `0 → 2`, `2 → 1`, из `0` сначала идём в `1`. К моменту рассмотрения `2 → 1` вызов для `1` завершён, но `1` ещё в `S`. Все три вершины образуют одну SCC. Проверка только серого цвета ошибочно выделила бы `{2}` отдельно.

Время — `O(n + m)`, дополнительная память — `O(n)`: каждая вершина один раз попадает в стек и один раз извлекается. Полное доказательство оставить за рамками этой пары согласно программе раздела.

## 8. Контрольные вопросы и типичные ошибки

| Вопрос аудитории | Ожидаемая мысль |
|---|---|
| Почему одного DFS недостаточно для SCC? | достижимость из старта не гарантирует обратный путь |
| Зачем Косарайю разворачивает дуги? | выбранная SCC становится стоком среди оставшихся |
| Можно ли во втором проходе идти по возрастанию выходов? | нет: на `a → b` старт из `b` в `GT` склеит разные SCC |
| `onStack` в Тарьяне означает серый цвет? | нет, завершившая рекурсивный вызов вершина может ждать в стеке SCC |

Обратить внимание на три практические ошибки: забытый внешний цикл DFS, использование старых меток при новом обходе, переполнение рекурсивного стека на длинной цепочке.
