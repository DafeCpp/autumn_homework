# Опорный конспект к лекции 3. Компоненты связности и значения low

## Откуда начинаем

Вторая лекция пройдена целиком: деревья обхода, `tin/tout`, лемма о белых путях и топологическая сортировка уже известны. Обратные рёбра DFS кратко обсуждали. Достаточно восстановить их смысл на рисунке; заново доказывать свойства времён обхода не требуется.

Фраза для начала: «В прошлый раз времена выхода помогли упорядочить вершины графа без циклов. Сегодня научимся сжимать циклы в компоненты, а затем искать рёбра и вершины, от которых зависит связность».

Обозначения: `n = |V|`, `m = |E|`, граф хранится списками смежности. Каждый алгоритм запускает собственный DFS со свежими массивами. Для `tin` достаточно увеличивать таймер только при входе; для Косарайю достаточно списка выходов без числовых `tout`.

## 1. Короткое повторение: обратные рёбра

Нарисовать треугольник `0—1—2—0`; DFS идёт `0 → 1 → 2`. Рёбра `0—1` и `1—2` — древесные, ребро `2—0` даёт возврат к предку.

- Древесное ребро впервые открывает вершину.
- Обратное ребро направлено из потомка к предку в дереве DFS.
- В неориентированном графе каждое недревесное ребро между различными вершинами соединяет предка и потомка. Поперечных рёбер между разными ветвями DFS нет: первая обработанная ветвь обнаружила бы вторую через такое ребро.
- Одно неориентированное ребро хранится в двух списках. Запись древесного ребра со стороны ребёнка не считается отдельным обратным ребром; пропускаем именно идентификатор ребра прихода.
- В орграфе возможны также прямые и поперечные рёбра. Свойства неориентированного дерева DFS нельзя переносить на него автоматически.

Вопрос: «Если между родителем и ребёнком два параллельных ребра, можно ли пропустить оба?» Ответ: нет, второе ребро даёт обход первого. Петля не может быть мостом.

## 2. Слабая и сильная связность

**Слабая компонента** орграфа — компонента связности после снятия направлений с рёбер. Находим обычным DFS/BFS по неориентированной версии графа.

**Компонента сильной связности (SCC)** — максимальное множество взаимно достижимых вершин. Отношение «`u` достижима из `v` и `v` достижима из `u`» рефлексивно, симметрично и транзитивно, поэтому SCC разбивают вершины на непересекающиеся классы. Одиночная вершина тоже может быть SCC.

Один обычный DFS орграфа не выделяет SCC: в графе `a → b` он посетит обе вершины, но обратного пути нет.

### Пример A: один граф для SCC

Вершины `0, 1, 2, 3, 4, 5, 6`. Дуги:

```text
0 → 1, 1 → 2, 2 → 0,
2 → 3,
3 → 4, 4 → 3,
4 → 5.
6 — изолированная вершина.
```

Перебирать старты и соседей по возрастанию номеров.

- Слабые компоненты: `{0,1,2,3,4,5}` и `{6}`.
- SCC: `A = {0,1,2}`, `B = {3,4}`, `C = {5}`, `D = {6}`.
- Конденсация: `A → B → C`, отдельно `D`.

### Почему конденсация ациклична

Сжимаем каждую SCC в одну вершину, сохраняем дуги между разными компонентами, внутренние дуги убираем. Если бы в конденсации был ориентированный цикл, все компоненты на нём были бы взаимно достижимы и составляли бы одну SCC. Это противоречит их максимальности.

Переход: «Топологически упорядочить исходные вершины мешают циклы. Компоненты уже можно упорядочить. Как получить этот порядок, ещё не зная самих компонент?»

## 3. Алгоритм Косарайю

### Алгоритм и псевдокод

1. Полный DFS по исходному графу `G`; при выходе добавлять вершину в `order`.
2. Построить `GT`, развернув каждую дугу.
3. Просмотреть `order` с конца. Из каждой ещё не назначенной вершины запустить DFS по `GT`; посещённые этим запуском вершины получают один номер SCC.

```text
visited = [false] * n
order = []
comp = [-1] * n

dfs1(v):
    visited[v] = true
    for to in G[v]:
        if not visited[to]:
            dfs1(to)
    order.push(v)

dfs2(v, id):
    comp[v] = id
    for to in GT[v]:
        if comp[to] == -1:
            dfs2(to, id)

for v in vertices:
    if not visited[v]:
        dfs1(v)

id = 0
for v in reversed(order):
    if comp[v] == -1:
        dfs2(v, id)
        id += 1
```

В примере A список выходов: `[5,4,3,2,1,0,6]`. Старты второго прохода: `6`, `0`, `3`, `5`; уже назначенные вершины пропускаются. Получаем `{6}`, `{0,1,2}`, `{3,4}`, `{5}`.

### Доказательство через времена выхода компонент

Обозначим `T(C) = max(tout[v])` по вершинам компоненты `C`. Для любой дуги конденсации `C → D` верно **`T(C) > T(D)`**.

Рассмотреть два случая по первой обнаруженной вершине из `C ∪ D`:

1. Первой открыта вершина `c` из `C`. Все вершины `C` и `D` ещё белые и достижимы из `c` по белым путям внутри этих компонент и через дугу `C → D`. По лемме о белых путях они попадут в поддерево `c` и завершатся до неё. Значит, `T(C) > T(D)`.
2. Первой открыта вершина из `D`. Из `D` нельзя достичь `C`, иначе это одна SCC. Этот вызов соберёт всю `D` и завершится до обнаружения любой вершины `C`. Снова `T(C) > T(D)`.

Теперь берём ещё не выделенную компоненту с максимальным `T`. В неё нет дуг из других оставшихся компонент в `G`, иначе у предшественника было бы большее `T`. Следовательно, в `GT` из неё нет дуг в другие оставшиеся компоненты.

Второй DFS не покинет эту SCC среди неназначенных вершин, но посетит её целиком: разворот дуг сохраняет сильную связность. Удаляем выделенную компоненту из рассмотрения и повторяем рассуждение.

Подчеркнуть: убывание времён относится к **максимумам по компонентам**. Не нужно утверждать, что все времена одной SCC больше всех времён следующей.

### Сложность и построение конденсации

Два обхода и разворот дуг занимают `O(n + m)`. Дополнительная память — `O(n + m)`, включая `GT`; массивы и стек DFS занимают `O(n)`.

После нахождения `comp` перебираем исходные дуги `u → v` и добавляем `comp[u] → comp[v]`, если номера различны. За `O(n + m)` получаем конденсацию, возможно с повторными дугами; для ацикличности они не мешают. Если нужны уникальные дуги, стоимость их удаления учитывать отдельно.

## 4. Тарьян для SCC: один DFS и стек

Дать алгоритм и смысл условий без полного доказательства. Здесь `lowScc` — служебная метка Тарьяна; далее для неориентированного графа будем использовать отдельную метку `low`.

- `index[v]` — номер открытия вершины.
- `S` — стек открытых вершин, ещё не отнесённых к готовой SCC.
- `onStack[v]` — принадлежность именно этому стеку.
- `lowScc[v]` начинается с `index[v]`, получает `lowScc` детей DFS и `index` уже открытых соседей, которые остаются в `S`.

```text
timer = 0
index = [-1] * n
lowScc = [-1] * n
onStack = [false] * n
S = []

tarjan(v):
    index[v] = lowScc[v] = timer++
    S.push(v)
    onStack[v] = true
    for to in G[v]:
        if index[to] == -1:
            tarjan(to)
            lowScc[v] = min(lowScc[v], lowScc[to])
        else if onStack[to]:
            lowScc[v] = min(lowScc[v], index[to])

    if lowScc[v] == index[v]:
        component = []
        repeat:
            u = S.pop()
            onStack[u] = false
            component.push(u)
        until u == v
        output(component)

for v in vertices:
    if index[v] == -1:
        tarjan(v)
```

Интуиция: если метка стала меньше `index[v]`, закрывать компоненту на `v` рано — она связана с более ранней незакрытой частью обхода. Равенство выделяет корень SCC; её вершины лежат на вершине `S` вплоть до `v` включительно.

В примере A компоненты снимаются в порядке `{5}`, `{4,3}`, `{2,1,0}`, `{6}`. Дуга `4 → 5` не объединяет компоненты: после выделения `{5}` её метка не уменьшает метку `4`.

**Стек SCC не совпадает со стеком рекурсии.** Мини-пример: `0 → 1`, `1 → 0`, `0 → 2`, `2 → 1`, из `0` сначала идём в `1`. К моменту рассмотрения `2 → 1` вызов для `1` завершён, но `1` ещё в `S`. Все три вершины образуют одну SCC. Проверка только серого цвета ошибочно выделила бы `{2}` отдельно.

Время — `O(n + m)`, дополнительная память — `O(n)`: каждая вершина один раз попадает в стек и один раз извлекается. Полное доказательство оставить за рамками этой пары согласно программе раздела.

## 5. Неориентированный граф: смысл low и мосты

Явно сменить модель: **до конца основной части граф неориентированный**. `low` ниже определяется через дерево DFS и обратные рёбра, без стека SCC.

**Мост** — ребро, удаление которого увеличивает число компонент связности. Недревесное ребро мостом быть не может: его концы уже соединены путём в дереве DFS.

### Определение и вычисление low

`low[v]` — минимальное `tin`, достижимое из `v` движением вниз по нулю или нескольким древесным рёбрам и затем по не более чем одному обратному ребру вверх. Ребро прихода в `v` исключается. Саму `v` тоже учитываем.

```text
low[v] = min(
    tin[v],
    tin[a] для обратных рёбер из v в предка a,
    low[to] для детей to в дереве DFS
)
```

Обоснование снизу вверх: допустимый путь либо остаётся в `v`, либо сразу использует обратное ребро, либо сначала входит в одно из дочерних поддеревьев. Эти случаи исчерпывают определение и дают три части минимума.

Для уже посещённого соседа берём `tin[to]`, для ребёнка после рекурсии — `low[to]`. Это разные случаи. В коде можно обработать и уже посещённого потомка через `tin[to]`: его время больше `tin[v]`, поэтому минимум не изменится.

### Критерий моста и доказательство

Для древесного ребра `v—to`, где `to` — ребёнок:

```text
v—to — мост  ⇔  low[to] > tin[v]
```

- Если `low[to] <= tin[v]`, из поддерева `to` есть обратное ребро в `v` или выше. Оно вместе с древесными путями даёт обход ребра `v—to`; ребро лежит на цикле и не является мостом.
- Если `low[to] > tin[v]`, такого выхода нет. Рёбер в соседние ветви DFS тоже нет. Единственная связь поддерева `to` с остальной компонентой — `v—to`; его удаление отделит поддерево.

### Пример B: мосты, точки и оба вида компонент

```text
Треугольник: 0—1, 1—2, 2—0.
Перемычка:  1—3.
Треугольник: 3—4, 4—5, 5—3.
Хвост:      3—6.
Вершина 7 изолирована.
```

DFS начинает с `0`, соседи по возрастанию. Таймер увеличиваем только на входе:

| Вершина | Родитель | tin | low после возврата |
|---:|---:|---:|---:|
| 0 | — | 0 | 0 |
| 1 | 0 | 1 | 0 |
| 2 | 1 | 2 | 0 |
| 3 | 1 | 3 | 3 |
| 4 | 3 | 4 | 3 |
| 5 | 4 | 5 | 3 |
| 6 | 3 | 6 | 6 |
| 7 | — | 7 | 7 |

Мосты: `1—3`, `3—6`. Попросить аудиторию сначала вычислить `low[5]`, затем поднять метку к `4` и `3`.

## 6. Точки сочленения

**Точка сочленения** — вершина, удаление которой вместе с инцидентными рёбрами увеличивает число компонент связности всего графа.

### Некорневая вершина

```text
v — точка сочленения  ⇔  есть ребёнок to с low[to] >= tin[v]
```

Если `low[to] >= tin[v]`, поддерево ребёнка не может выйти к строгому предку `v`, минуя `v`. После её удаления оно отделится от части с родителем `v`. Возврат ровно в `v` не спасает: сама `v` удаляется.

Если для каждого ребёнка `low[to] < tin[v]`, каждое дочернее поддерево имеет выход к строгому предку. После удаления `v` все они остаются соединены с частью, содержащей её родителя, так что число компонент не увеличивается.

### Корень DFS

Корень — точка сочленения **тогда и только тогда, когда у него не менее двух детей в дереве DFS**. У разных дочерних поддеревьев нет рёбер друг к другу. Один ребёнок означает, что все остальные вершины этой компоненты лежат в одном связном поддереве; ноль детей означает изолированную вершину.

Не путать число детей DFS со степенью. В примере B у `0` два соседа, но один ребёнок DFS; `0` не является точкой сочленения. Точки сочленения — `1` и `3`.

### Почему в одном критерии >, а в другом >=

Для ребёнка `4` вершины `3` в примере B: `low[4] = tin[3] = 3`.

- Ребро `3—4` не мост: есть обход `3—5—4`.
- При удалении вершины `3` этот обход тоже исчезнет; `{4,5}` отделится. Поэтому равенства достаточно для точки сочленения.

### Общий псевдокод мостов и точек сочленения

Каждое неориентированное ребро имеет уникальный `id`, одинаковый в обеих записях смежности. Код допускает параллельные рёбра и петли.

```text
timer = 0
tin = [-1] * n
low = [-1] * n
isCut = [false] * n
bridges = []

dfs(v, parentEdge):
    tin[v] = low[v] = timer++
    children = 0
    for (to, id) in adj[v]:
        if id == parentEdge:
            continue
        if tin[to] == -1:
            children += 1
            dfs(to, id)
            low[v] = min(low[v], low[to])
            if low[to] > tin[v]:
                bridges.push(id)
            if parentEdge != -1 and low[to] >= tin[v]:
                isCut[v] = true
        else:
            low[v] = min(low[v], tin[to])
    if parentEdge == -1 and children >= 2:
        isCut[v] = true

for v in vertices:
    if tin[v] == -1:
        dfs(v, -1)
```

Время — `O(n + m)`, дополнительная память — `O(n + m)` с учётом результата; массивы и рекурсия занимают `O(n)`. Одна вершина может удовлетворить критерию несколько раз, поэтому отмечаем её булевым флагом.

## 7. Компоненты двусвязности

### Рёберная двусвязность

Удаляем все мосты и запускаем обычный DFS/BFS. Полученные множества вершин — компоненты рёберной двусвязности; одиночные вершины допускаем. Внутри каждой удаление одного ребра не нарушает связность. Это разбиение **вершин**, а мосты соединяют разные компоненты.

В примере B: `{0,1,2}`, `{3,4,5}`, `{6}`, `{7}`. Если сжать их, мосты образуют лес: цикл из мостов дал бы обход каждого из них, что невозможно. На каждую исходную связную компоненту приходится одно дерево этого леса.

Нахождение мостов и повторный обход суммарно занимают `O(n + m)`.

### Вершинная двусвязность и блоки

Для этого подраздела берём простой неориентированный граф. Блоки — максимальные связные подграфы без собственных точек сочленения. Используем соглашение: мост с концами — отдельный блок из двух вершин, изолированная вершина — отдельный одноэлементный блок. Невырожденные двусвязные блоки содержат не менее трёх вершин.

Блоки могут пересекаться по точкам сочленения. Каждое ребро принадлежит ровно одному блоку; вершина может принадлежать нескольким. Нельзя получить блоки простым удалением точек сочленения: они входят в сами блоки.

В примере B блоки по множествам вершин: `{0,1,2}`, `{1,3}`, `{3,4,5}`, `{3,6}`, `{7}`.

### Как выделять блоки стеком рёбер

Дополняем неориентированный DFS отдельным стеком `edgeStack`:

1. Перед рекурсией по древесному ребру кладём его `id` в стек.
2. Недревесное ребро кладём только при просмотре из потомка к предку (`tin[to] < tin[v]`), чтобы не положить его дважды. Ребро прихода по-прежнему пропускаем.
3. После возврата из ребёнка `to`, если `low[to] >= tin[v]`, снимаем рёбра до древесного `v—to` включительно. Это один блок; его вершины — концы снятых рёбер.
4. Изолированную вершину выдаём отдельно: она не положит в стек ни одного ребра.

Условие извлечения блока используется **и для корня**. Специальное правило о двух детях нужно только для отметки корня как точки сочленения.

Идея корректности: при `low[to] >= tin[v]` накопленная часть не соединяется со строгими предками `v` в обход `v`, поэтому здесь проходит граница блока. Более глубокие границы уже обработаны; оставшиеся сверху рёбра образуют очередной максимальный блок.

В примере B при возврате из `2` блок ещё не снимается; при возврате из `4` снимается треугольник `{3,4,5}`, из `6` — ребро `3—6`, из `3` — ребро `1—3`, из `1` — треугольник `{0,1,2}`.

Каждое ребро кладётся и снимается один раз, время — `O(n + m)`, память для стека и результата — `O(n + m)`. Для выдачи уникальных вершин блока можно использовать массив меток с номером текущего блока, не очищая массив размера `n` на каждом извлечении.

## 8. Контрольные вопросы и типичные ошибки

| Вопрос аудитории | Ожидаемая мысль |
|---|---|
| Почему одного DFS недостаточно для SCC? | достижимость из старта не гарантирует обратный путь |
| Зачем Косарайю разворачивает дуги? | выбранная SCC становится стоком среди оставшихся |
| Можно ли во втором проходе идти по возрастанию выходов? | нет: на `a → b` старт из `b` в `GT` склеит разные SCC |
| `onStack` в Тарьяне означает серый цвет? | нет, завершившая рекурсивный вызов вершина может ждать в стеке SCC |
| Почему обратное ребро обновляет через `tin`, а не через `low`? | оно учитывает один переход к его концу согласно формуле |
| Почему равенство допустимо для точки, но не для моста? | возврат в удаляемую вершину не сохраняет связность |
| Корень степени 2 всегда точка сочленения? | нет, важны дети DFS; контрпример — треугольник |
| Почему нельзя пропускать все рёбра в родителя? | параллельное ребро может давать обход |
| В чём различие двух видов компонент? | рёберные компоненты разбивают вершины, вершинные блоки могут пересекаться |

Обратить внимание на три практические ошибки: забытый внешний цикл DFS, использование старых меток при новом обходе, переполнение рекурсивного стека на длинной цепочке.

## 9. Резерв из лекции 4: эйлеровы пути

Резерв проходить только после основной части. Подробности планарности остаются на лекцию 4. Здесь предусмотрено до 20 минут готового материала, который можно остановить после любого блока.

### Блок A — 5 минут: постановка и неориентированный критерий

Переход: «До сих пор мы изучали, что произойдёт после удаления ребра. Теперь поставим задачу пройти по каждому ребру ровно один раз».

**Эйлеров путь** здесь означает маршрут, использующий каждое ребро ровно один раз; вершины повторять можно. Если начало совпадает с концом, получаем эйлеров цикл. Не путать с гамильтоновым путём, где условие относится к вершинам.

Для графа с хотя бы одним ребром все вершины ненулевой степени должны лежать в одной компоненте связности. Изолированные вершины не мешают.

- Эйлеров цикл существует тогда и только тогда, когда дополнительно все степени чётны.
- Незамкнутый эйлеров путь существует тогда и только тогда, когда ровно две степени нечётны; эти вершины — его концы.
- Если разрешён и замкнутый путь, нечётных вершин должно быть **0 или 2**.

Необходимость: во внутренних вершинах каждый приход спаривается с уходом. Достаточность будет следовать из алгоритма следующего блока. При двух нечётных вершинах можно добавить между ними фиктивное ребро, найти цикл и разрезать его по этому ребру.

Пример: два треугольника `0—1—2—0` и `0—3—4—0` имеют эйлеров цикл, хотя `0` — точка сочленения. Если добавить ребро `4—5`, получим незамкнутый путь из `4` в `5`. Два раздельных треугольника показывают, почему одной чётности мало.

**Точка остановки:** определения, необходимость критериев и примеры известны; достаточность и построение начать на лекции 4.

### Блок B — ещё 5 минут: ориентированный критерий

Пусть `delta[v] = outdeg[v] - indeg[v]`. Требуем слабую связность всех вершин ненулевой суммарной степени.

| Маршрут | Условия на степени | Старт |
|---|---|---|
| Эйлеров цикл | `delta[v] = 0` для всех | любая вершина с исходящим ребром |
| Незамкнутый путь `s → t` | `delta[s] = 1`, `delta[t] = -1`, у остальных `0` | `s` |

Необходимость снова следует из баланса приходов и уходов. Для открытого пути добавляем дугу `t → s`, получаем сбалансированный граф и сводим задачу к циклу.

Связь с сегодняшней темой: почему для цикла достаточно **слабой** связности и баланса? Рассмотрим конденсацию и её источник. Сумма `outdeg - indeg` внутри SCC равна числу выходящих наружу дуг минус число входящих. Если входящих нет, баланс запрещает и выходящие. При нескольких SCC это противоречит слабой связности. Значит, все вершины с рёбрами лежат в одной SCC.

Пример: `0 → 1 → 2 → 0` и дополнительная дуга `0 → 3`. У `0` баланс `+1`, у `3` — `-1`; путь `0,1,2,0,3` использует все дуги.

**Точка остановки:** оба критерия сформулированы; построение и достаточность остаются на лекцию 4.

### Блок C — ещё 10 минут: алгоритм Хиерхольцера

Идея для цикла: идём по неиспользованным рёбрам. Баланс не позволит застрять вне старта. Если рёбра остались, из некоторой вершины построенного маршрута начинается ещё один цикл; вставляем его в текущий. Стек реализует такие вставки без явного склеивания списков.

Перед запуском проверить критерий и выбрать старт: нечётная вершина для незамкнутого неориентированного пути, вершина баланса `+1` для ориентированного; иначе любая вершина с рёбрами. При `m = 0` договориться выдавать одну произвольную вершину, если она есть, иначе пустой маршрут.

```text
used = [false] * m
ptr = [0] * n
stack = [start]
answer = []

while stack is not empty:
    v = stack.top()
    while ptr[v] < len(adj[v]) and used[adj[v][ptr[v]].id]:
        ptr[v] += 1
    if ptr[v] == len(adj[v]):
        answer.push(stack.pop())
    else:
        (to, id) = adj[v][ptr[v]]
        ptr[v] += 1
        used[id] = true
        stack.push(to)

answer.reverse()
if len(answer) != m + 1:
    report "Маршрута по всем рёбрам нет"
```

В неориентированном графе обе записи ребра имеют один `id`, в ориентированном храним только исходящие дуги. Проверка длины подтверждает использование всех рёбер при выполненных условиях на степени и правильном старте; сама по себе она не заменяет критерии существования.

Трассировка на двух треугольниках из блока A: начинаем `0,1,2,0,3,4,0`, затем снимаем стек. После разворота получаем цикл. Если сначала замкнули один треугольник, оставшийся проход через `0` вставится в него — это и есть идея алгоритма.

Почему достаточно: из-за чётности (или баланса) очередной проход в задаче о цикле замыкается. После его удаления баланс сохраняется. Пока есть неиспользованные рёбра, связность обеспечивает вершину текущего маршрута, из которой можно продолжить построение. Все рёбра постепенно включаются во вставляемые циклы. Открытый случай сводится к циклу добавлением фиктивного ребра; прямой запуск из нужного старта строит тот же тип маршрута.

Время — `O(n + m)` вместе с проверками: каждый указатель проходит свой список один раз. Память — `O(n + m)`, стек может содержать `m + 1` вхождений вершин. Это алгоритм Хиерхольцера; пересчитывать мосты и выбирать «не мост» на каждом шаге здесь не нужно.

**Точка остановки:** эйлеровы пути разобраны полностью в объёме этого резерва. На лекции 4 коротко проверить понимание и перейти к планарности.
