## 1. Повторение: Форд—Беллман и восстановление пути — 5 минут

```text
d = [∞] * n
parent = [-1] * n
d[s] = 0
repeat n - 1 times:
    for (u, v, w) in edges:
        if d[u] != ∞ and d[u] + w < d[v]:
            d[v] = d[u] + w
            parent[v] = u
```

Два факта, на которые сегодня опираемся:

- **Оценка сверху.** Любая конечная `d[v]` — вес некоторого маршрута из `s` в `v`, поэтому всегда `d[v] >= δ(s,v)`.
- **Свойство релаксации пути.** Если `s = v_0 → v_1 → … → v_k = v` — путь, то после `i` проходов `d[v_i] <= w(v_0 … v_i)`: к `i`-му проходу префикс уже «протащен» хотя бы на `i` дуг. Если `δ(s,v)` конечно, то на маршрутах в `v` нет отрицательных циклов, кратчайший путь простой и содержит не более `n - 1` дуг, значит после `n - 1` проходов `d[v] = δ(s,v)`. Это верно для каждой такой `v`, **даже если отрицательные циклы есть в другой части графа**.

Восстановление пути: при каждом строгом улучшении запоминаем `parent[v]` (и `parentEdge[v]`, если есть параллельные дуги); путь до `t` — цепочка предков от `t` до `s`, развёрнутая. Сегодня добавится оговорка: **по предкам можно идти только до вершин с конечным ответом** — иначе цепочка может зациклиться (раздел 2).

Мини-проверка на примере B лекции 6 (`s → a (2)`, `s → b (5)`, `b → a (-4)`, `a → t (3)`, `b → t (6)`): `d = (s 0, a 1, b 5, t 4)`, `parent[a] = b`, `parent[b] = s`, `parent[t] = a`, путь `s → b → a → t` весом 4.

Проверка `d[u] != ∞` обязательна: иначе `∞ + (отрицательное)` в коде с числовым `INF` создаст несуществующий маршрут.

## 2. Отрицательный цикл: обнаружение и восстановление — 15 минут

### Критерий `n`-го прохода

После `n - 1` проходов делаем ещё один, `n`-й, и запоминаем вершины, оценка которых улучшилась.

**Утверждение.** Хотя бы одна оценка улучшается на `n`-м проходе тогда и только тогда, когда из `s` достижим отрицательный цикл.

**Цикл есть ⇒ улучшение будет.** Пусть `C = v_0 → v_1 → … → v_k = v_0`, `w(C) < 0`, и `C` достижим из `s` — тогда все `d[v_i]` конечны. Предположим, что за `n`-й проход ни одна вершина цикла не изменилась. Тогда значения `d` на `C` весь проход постоянны, каждая дуга цикла была проверена с этими значениями и не сработала:

```text
d[v_i] <= d[v_(i-1)] + w(v_(i-1), v_i)   для всех i = 1..k
```

Сложим по циклу: суммы `d` слева и справа одинаковы (каждая вершина цикла встречается по разу), остаётся `0 <= w(C)` — противоречие.

Подсказка к доске: «предполагаем, что *ни одна вершина цикла* не изменилась», а не «ни одна дуга не сработала». При обновлении на месте вершина цикла может уменьшиться через постороннюю дугу уже после проверки своей дуги цикла — тогда неравенства не выполняются одновременно, и рассуждение рушится.

**Улучшение было ⇒ цикл есть.** Пусть на `n`-м проходе улучшилась `d[x]` через дугу `u → x`. Если бы `δ(s,x)` было конечно, то по свойству релаксации пути уже после `n - 1` проходов `d[x] = δ(s,x)`. Но новое значение `d[u] + w(u,x)` — вес некоторого маршрута в `x`, меньший `δ(s,x)`. Противоречие, значит `δ(s,x) = -∞`, а это бывает только при отрицательном цикле, достижимом из `s` (и из которого достижима `x`).

Время: `n` проходов — `O(nm)`, дополнительная память `O(n)`.

**Ранний выход** «проход без изменений ⇒ стоп» сохраняет корректность: если проход ничего не изменил, все следующие тоже ничего не изменят, в том числе `n`-й, — значит отрицательного цикла, достижимого из `s`, нет.

### Восстановление цикла

```text
x = последняя вершина, улучшенная на n-м проходе
repeat n times:
    x = parent[x]          # теперь x лежит на цикле в графе предков
cycle = [x]
v = parent[x]
while v != x:
    cycle.push(v)
    v = parent[v]
cycle.reverse()            # вершины цикла в порядке дуг
```

Почему не начинать сразу с улучшенной вершины: она может лишь **достигаться** из цикла, а не лежать на нём. `n` шагов назад гарантированно приводят на цикл предков — «хвост» до цикла короче `n`; этот факт даём без строгого доказательства. Цикл может проходить и через `s`, если `s` сама лежит на отрицательном цикле — тогда `parent[s]` тоже будет установлен.

**Доказываем строго: любой цикл в графе предков отрицателен.** Пусть цикл замыкается в момент, когда ставим `parent[v] = u`. Для каждой другой дуги цикла `u_i → v_i` (`parent[v_i] = u_i`) в момент установки было `d[v_i] = d[u_i] + w_i`. Дальше `d[u_i]` могло только уменьшиться, а `d[v_i]` менялось только при новой релаксации: через другую вершину — тогда сменился бы предок; через ту же `u_i` — снова равенство. Значит, всегда `d[v_i] >= d[u_i] + w_i`. Для замыкающей дуги до обновления строго: `d[v] > d[u] + w(u,v)`. Суммируем по циклу — получаем `0 > w(C)`.

### Пример E — трассировка на доске

```text
дуги в порядке обработки:
s → a (2), a → b (3), b → c (-4), c → a (0), c → d (1),
s → e (5), e → d (2), s → d (-20), f → f (-1)
```

Вершины `s, a, b, c, d, e, f`, `n = 7`. Цикл `a → b → c → a` весит `3 - 4 + 0 = -1`; из него достижима `d`. Вершина `f` недостижима из `s`, её отрицательная петля на ответ из `s` не влияет.

| После прохода | a | b | c | d | e | f | Улучшены |
|---|---:|---:|---:|---:|---:|---:|---|
| 1 | 1 | 5 | 1 | -20 | 5 | ∞ | a, b, c, a, d, e, d |
| 2 | 0 | 4 | 0 | -20 | 5 | ∞ | b, c, a |
| 3 | -1 | 3 | -1 | -20 | 5 | ∞ | b, c, a |
| 4 | -2 | 2 | -2 | -20 | 5 | ∞ | b, c, a |
| 5 | -3 | 1 | -3 | -20 | 5 | ∞ | b, c, a |
| 6 | -4 | 0 | -4 | -20 | 5 | ∞ | b, c, a |
| 7 (проверочный) | -5 | -1 | -5 | -20 | 5 | ∞ | b, c, a |

На первом проходе `a` улучшается дважды: сначала `2` по `s → a`, затем `1` по `c → a`. Дуга `f → f` ни разу не релаксируется: `d[f] = ∞`.

Восстановление: последней на 7-м проходе улучшилась `a`. Семь шагов по предкам: `a → c → b → a → c → b → a → c`, останавливаемся в `c`. Обходим цикл предков от `c`: `parent[c] = b`, `parent[b] = a`, `parent[a] = c`; после разворота — цикл `a → b → c → a` весом `-1`.

## 3. Все вершины с ответом `-∞` — 10 минут

**Утверждение.** `δ(s,v) = -∞` тогда и только тогда, когда `v` достижима из какой-либо вершины, улучшенной на `n`-м проходе.

- ⇐: улучшенная вершина `x` имеет `δ(s,x) = -∞` (раздел 2), а маршруты сколь угодно малой стоимости продолжаются по любым дугам — `-∞` распространяется на всё достижимое из `x`.
- ⇒: если `δ(s,v) = -∞`, существует отрицательный цикл `C`, достижимый из `s`, из которого достижима `v`. На `n`-м проходе улучшается хотя бы одна вершина `C` (раздел 2), а из неё достижим весь `C` и, значит, `v`.

```text
bellman_ford_full(s):
    n - 1 проходов как в разделе 1
    improved = все v, у которых d[v] уменьшилось на n-м проходе
    negInf = BFS/DFS по исходным дугам из всех improved
    для каждой v:
        v ∈ negInf  → ответ -∞
        d[v] == ∞   → ответ +∞ (недостижима)
        иначе       → ответ d[v], путь по parent корректен
```

Время `O(nm + n + m) = O(nm)` при `m >= 1`; память `O(n)`.

**Главная ловушка — на примере E.** На 7-м проходе улучшились только `a, b, c`. Вершина `d` **не** улучшилась: `d[d] = -20` держится по дуге `s → d`, а цикл за 7 проходов опустил `c` только до `-5`. Но `d` достижима из цикла, и `δ(s,d) = -∞`. Итог по примеру E:

| Вершина | s | a | b | c | d | e | f |
|---|---:|---:|---:|---:|---:|---:|---:|
| Ответ | 0 | -∞ | -∞ | -∞ | -∞ | 5 | +∞ |

Вопросы аудитории:

- «Почему `d[d] = -20` — неверный ответ, хотя он не менялся шесть проходов?» `c` уменьшается на 1 за проход; ещё через 17 проходов `c` опустится до `-22`, и `d` начнёт уменьшаться по дуге `c → d`. Стабильность значения ничего не доказывает.
- «Почему `e = 5` верно?» Из `e` можно уйти в `d`, но в `e` нельзя прийти из цикла; `-∞` распространяется только **вперёд** по дугам.
- «Почему `f` не `-∞`, хотя на ней отрицательная петля?» Она недостижима из `s`. Для задачи с одним источником такой цикл не важен; для задачи всех пар (Флойд, Джонсон, `task_04`) — важен.

Альтернатива, которую студенты часто приносят: сделать ещё `n` проходов, присваивая `-∞` при любом улучшении и распространяя `-∞` по дугам. Это тоже корректно, но вдвое дороже; обход из улучшенных вершин проще обосновать.

## 4. Флойд—Уоршелл: динамика и доказательство — 17 минут

Задача всех пар. Вершины нумеруем `1..n`.

**Определение.** `dist_k[i][j]` — минимальный вес пути из `i` в `j`, все **промежуточные** вершины которого (кроме концов) лежат в `{1, …, k}`; `∞`, если такого пути нет.

```text
dist_0[i][i] = min(0, минимальный вес петли i → i)
dist_0[i][j] = минимальный вес дуги i → j  (∞, если дуги нет), i ≠ j
dist_k[i][j] = min(dist_(k-1)[i][j], dist_(k-1)[i][k] + dist_(k-1)[k][j])
```

**Корректность при отсутствии отрицательных циклов** — индукция по `k`.

- *Значение достижимо.* Каждое конечное `dist_k[i][j]` — вес некоторого маршрута `i ⇝ j` с промежуточными из `{1..k}` (склейка двух таких маршрутов через `k`). Без отрицательных циклов вес маршрута не меньше веса кратчайшего простого пути с теми же концами и промежуточными вершинами из того же множества: удаление циклов вес не увеличивает. Значит, `dist_k[i][j] >= OPT_k[i][j]`.
- *Значение оптимально.* Возьмём кратчайший простой путь `P` с промежуточными из `{1..k}`. Если `k ∉ P`, его промежуточные из `{1..k-1}` и `w(P) >= dist_(k-1)[i][j]`. Если `k ∈ P`, то ровно один раз (путь простой); `P` разбивается на `i ⇝ k` и `k ⇝ j` с промежуточными из `{1..k-1}`, и `w(P) >= dist_(k-1)[i][k] + dist_(k-1)[k][j]`. В обоих случаях `dist_k[i][j] <= w(P) = OPT_k[i][j]`.

Ответ — `dist_n`: при `k = n` разрешены все промежуточные вершины.

```text
for k in 1..n:                      # k — ВНЕШНИЙ цикл
    for i in 1..n:
        if dist[i][k] == ∞: continue
        for j in 1..n:
            if dist[k][j] != ∞ and dist[i][k] + dist[k][j] < dist[i][j]:
                dist[i][j] = dist[i][k] + dist[k][j]
                next[i][j] = next[i][k]
```

**Почему хватает одной матрицы.** На фазе `k` строка `k` и столбец `k` не меняются: `dist[i][k] + dist[k][k] >= dist[i][k]`, пока `dist[k][k] >= 0`. Значит, в фазе `k` все читаемые `dist[i][k]` и `dist[k][j]` равны значениям `dist_(k-1)`. Если `dist[k][k] < 0`, отрицательный цикл уже найден, и точные значения не важны.

**Почему `k` — внешний.** Динамика идёт по множеству разрешённых промежуточных вершин; при `k` во внутреннем цикле на момент обработки пары `(i, j)` значения `dist[i][k]` и `dist[k][j]` ещё не оптимальны для нужного множества. Это частая ошибка — на контрольной её не прощают.

Асимптотика: `O(n³)` времени, `O(n²)` памяти; матрица `next` — ещё `O(n²)`.

## 5. Флойд на примере: путь, отрицательные циклы, классификация пар — 13 минут

### Пример F — трассировка

```text
1 → 2 (3), 2 → 3 (-2), 1 → 3 (6), 3 → 4 (2), 4 → 1 (1), 4 → 2 (4)
```

Отрицательных циклов нет: `1 → 2 → 3 → 4 → 1` весит 4, `2 → 3 → 4 → 2` весит 4.

Начальная матрица (строка — откуда, столбец — куда):

| | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|
| 1 | 0 | 3 | 6 | ∞ |
| 2 | ∞ | 0 | -2 | ∞ |
| 3 | ∞ | ∞ | 0 | 2 |
| 4 | 1 | 4 | ∞ | 0 |

| Фаза | Изменения (`next` после изменения) |
|---|---|
| k = 1 | `dist[4][3] = 1 + 6 = 7`, `next[4][3] = 1` |
| k = 2 | `dist[1][3] = 3 - 2 = 1`, `next[1][3] = 2`; `dist[4][3] = 4 - 2 = 2`, `next[4][3] = 2` |
| k = 3 | `dist[1][4] = 1 + 2 = 3`, `next[1][4] = 2`; `dist[2][4] = -2 + 2 = 0`, `next[2][4] = 3` |
| k = 4 | `dist[2][1] = 0 + 1 = 1`, `next[2][1] = 3`; `dist[3][1] = 2 + 1 = 3`, `next[3][1] = 4`; `dist[3][2] = 2 + 4 = 6`, `next[3][2] = 4` |

Итог:

| | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|
| 1 | 0 | 3 | 1 | 3 |
| 2 | 1 | 0 | -2 | 0 |
| 3 | 3 | 6 | 0 | 2 |
| 4 | 1 | 4 | 2 | 0 |

Обратить внимание: `dist[4][3]` улучшалось дважды (7, затем 2) — первое значение не окончательное, как и в Дейкстре до фиксации.

### Восстановление пути

`next[i][j]` — первая вершина после `i` на текущем лучшем пути. Инициализация: `next[i][j] = j` для дуги `i → j`, `next[i][i] = i`. При улучшении через `k`: `next[i][j] = next[i][k]`.

```text
path(i, j):
    if dist[i][j] == ∞: return "пути нет"
    p = [i]
    while i != j:
        i = next[i][j]
        p.push(i)
    return p
```

Пример F, путь `2 → 1`: `next[2][1] = 3`, `next[3][1] = 4`, `next[4][1] = 1` — путь `2 → 3 → 4 → 1`, вес `-2 + 2 + 1 = 1`, совпадает с `dist[2][1]`. Путь `3 → 2`: `3 → 4 → 2`, вес 6.

Альтернатива — хранить `mid[i][j] = k` последней улучшившей вершины и восстанавливать рекурсивно `path(i, k) + path(k, j)`. Вариант с `next` проще и не требует рекурсии.

### Отрицательные циклы и классификация пар

**Обнаружение.** Отрицательный цикл есть тогда и только тогда, когда после алгоритма `dist[v][v] < 0` хотя бы для одной `v`.

Подсказка к доказательству: каждое значение — вес некоторого замкнутого маршрута, поэтому `dist[v][v] < 0` даёт отрицательный замкнутый маршрут, а в нём есть отрицательный простой цикл. Обратно: пусть `C` — простой отрицательный цикл. Если это петля, `dist[v][v] < 0` уже при инициализации. Иначе пусть `k` — вершина `C` с **наибольшим номером**, `v` — любая другая вершина `C`. Участки цикла `v ⇝ k` и `k ⇝ v` используют промежуточные вершины с номерами меньше `k`, поэтому к фазе `k` уже `dist[v][k] <= w(v ⇝ k)` и `dist[k][v] <= w(k ⇝ v)`, и на фазе `k` получаем `dist[v][v] <= dist[v][k] + dist[k][v] <= w(C) < 0`. Значения только уменьшаются — к концу `dist[v][v] < 0`.

**Классификация пары `(i, j)`** после основного алгоритма:

```text
dist[i][j] == ∞                                        → +∞ (пути нет)
есть t: dist[t][t] < 0, dist[i][t] < ∞, dist[t][j] < ∞  → -∞
иначе                                                   → dist[i][j], путь по next корректен
```

Проверка второго условия — ещё `O(n³)`. По доказательству выше у каждого отрицательного цикла есть вершина `t` с `dist[t][t] < 0`; через неё маршрут `i ⇝ t ⇝ j` можно «прокрутить» сколько угодно раз.

### Пример G — классификация

```text
1 → 2 (1), 2 → 3 (-1), 3 → 2 (-1), 3 → 4 (1)
```

Цикл `2 → 3 → 2` весит `-2`. После Флойда диагональ: `dist[1][1] = 0`, `dist[2][2] = -2`, `dist[3][3] = -4`, `dist[4][4] = 0` (у `3` значение ниже веса цикла: на фазе 3 отрицательное `dist[3][3] = -2` складывается само с собой, `-2 + (-2) = -4`; точные числа при отрицательных циклах смысла не имеют).

| из \ в | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 1 | 0 | -∞ | -∞ | -∞ |
| 2 | +∞ | -∞ | -∞ | -∞ |
| 3 | +∞ | -∞ | -∞ | -∞ |
| 4 | +∞ | +∞ | +∞ | 0 |

Обратить внимание: `(1, 1) = 0` — из `1` можно попасть в цикл, но вернуться в `1` нельзя; `(4, 4) = 0` — из цикла в `4` попасть можно, но из `4` никуда нельзя.

Практика: при отрицательных циклах значения могут убывать экспоненциально по числу фаз — в коде ограничивать снизу (например, `max(dist, -INF)`) или сразу классифицировать. Восстанавливать путь по `next` можно только для пар третьей категории: для пар с `-∞` проход по `next` может зациклиться.

## 6. Алгоритм Джонсона — 18 минут

Задача всех пар в **разреженном** графе с отрицательными дугами. Флойд даёт `O(n³)` независимо от `m`; `n` запусков Дейкстры дали бы `O(n(n + m) log n)`, но Дейкстра не работает с отрицательными дугами. Идея: найти потенциал, после которого все веса неотрицательны (лекция 6), и только потом запускать Дейкстру.

### Шаги

1. Добавить вершину `q` и дуги `q → v` веса 0 для всех `v`.
2. Форд—Беллман из `q`. В графе `n + 1` вершина, поэтому нужно `n` проходов и проверочный `n + 1`-й. Если проверочный проход что-то улучшил — в графе есть отрицательный цикл: сообщить и остановиться. Из `q` достижима любая вершина, значит, проверка ловит **любой** отрицательный цикл, даже в изолированной компоненте.
3. Потенциал `h(v) = δ(q,v)`. Он конечен (все вершины достижимы, отрицательных циклов нет) и `h(v) <= 0` (есть дуга `q → v` веса 0).
4. Новые веса `w_h(u,v) = w(u,v) + h(u) - h(v)`.
5. Из каждой `u` запустить Дейкстру по `w_h` и вернуть `δ(u,v) = δ_h(u,v) - h(u) + h(v)` для достижимых `v`; недостижимые остаются `+∞`.

### Доказательства

**Неотрицательность новых весов.** Для расстояний от `q` выполняется неравенство треугольника: `δ(q,v) <= δ(q,u) + w(u,v)` — путь в `u` плюс дуга `u → v` есть маршрут в `v`. Переносим: `w(u,v) + h(u) - h(v) >= 0`, т.е. ровно `w_h(u,v) >= 0`.

**Кратчайшие пути сохраняются.** Для любого маршрута `P` из `u` в `v` промежуточные потенциалы сокращаются (телескопическая сумма, лекция 6):

```text
w_h(P) = w(P) + h(u) - h(v)
```

У всех маршрутов с одинаковыми концами одна и та же прибавка, поэтому порядок по весу и множество кратчайших путей не меняются. Отсюда обратная формула `δ(u,v) = δ_h(u,v) - h(u) + h(v)`.

**Почему фиктивная `q`, а не произвольная вершина графа.** От произвольной вершины могут быть недостижимы части графа: `h = ∞` нельзя подставить в формулу. Дуги `q → v` веса 0 делают все вершины достижимыми и не создают новых циклов (в `q` ничего не входит), поэтому ответы для исходных пар не меняются.

Связь со знаками: здесь потенциал — расстояние **от** фиктивного источника, `p = h`. В A* был `p = -h_A*`, где `h_A*` — оценка расстояния **до** цели. Обе формулы — частные случаи `w + p(u) - p(v)`.

### Пример H — на доске

```text
1 → 2 (3), 1 → 3 (8), 1 → 5 (-4), 2 → 4 (1), 2 → 5 (7),
3 → 2 (4), 4 → 1 (2), 4 → 3 (-5), 5 → 4 (6)
```

Шаг 2. Дуги `q → v` сразу дают `h = 0` для всех `v`; далее проходы по исходным дугам в записанном порядке:

| После прохода | h(1) | h(2) | h(3) | h(4) | h(5) |
|---|---:|---:|---:|---:|---:|
| дуги из `q` | 0 | 0 | 0 | 0 | 0 |
| 1 | 0 | 0 | -5 | 0 | -4 |
| 2 | 0 | -1 | -5 | 0 | -4 |
| 3 | 0 | -1 | -5 | 0 | -4 |

Третий проход изменений не дал — дальше ничего не изменится, отрицательных циклов нет. `h = (0, -1, -5, 0, -4)`.

Шаг 4. Новые веса:

| Дуга | `w` | `h(u) - h(v)` | `w_h` |
|---|---:|---:|---:|
| 1 → 2 | 3 | 0 - (-1) = 1 | 4 |
| 1 → 3 | 8 | 0 - (-5) = 5 | 13 |
| 1 → 5 | -4 | 0 - (-4) = 4 | 0 |
| 2 → 4 | 1 | -1 - 0 = -1 | 0 |
| 2 → 5 | 7 | -1 - (-4) = 3 | 10 |
| 3 → 2 | 4 | -5 - (-1) = -4 | 0 |
| 4 → 1 | 2 | 0 - 0 = 0 | 2 |
| 4 → 3 | -5 | 0 - (-5) = 5 | 0 |
| 5 → 4 | 6 | -4 - 0 = -4 | 2 |

Все `w_h >= 0`.

Шаг 5 — Дейкстра из `2` по `w_h`: фиксация `2 (0)`, `4 (0)`, `3 (0)`, `1 (2)`, `5 (2)`; итого `δ_h(2, ·) = (2, 0, 0, 0, 2)`. Обратный пересчёт `δ(2,v) = δ_h(2,v) - h(2) + h(v) = δ_h(2,v) + 1 + h(v)`:

| v | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| `δ_h(2,v)` | 2 | 0 | 0 | 0 | 2 |
| `+ 1 + h(v)` | +1 | 0 | -4 | +1 | -3 |
| `δ(2,v)` | 3 | 0 | -4 | 1 | -1 |

Проверка: `2 → 4 → 3` весит `1 - 5 = -4`; `2 → 4 → 1 → 5` весит `1 + 2 - 4 = -1`. Совпадает с ответом Флойда для этого графа. Полная матрица (для проверки дома):

| | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| 1 | 0 | 1 | -3 | 2 | -4 |
| 2 | 3 | 0 | -4 | 1 | -1 |
| 3 | 7 | 4 | 0 | 5 | 3 |
| 4 | 2 | -1 | -5 | 0 | -2 |
| 5 | 8 | 5 | 1 | 6 | 0 |

### Асимптотика

Форд—Беллман на `n + 1` вершине и `m + n` дугах — `O(n(n + m))`; перевзвешивание `O(m)`; `n` запусков Дейкстры с бинарной кучей — `O(n(n + m) log n)`. Итого `O(n(n + m) log n)`, при `m >= n` пишут `O(nm log n)`. С фибоначчиевой кучей — `O(nm + n² log n)`, без доказательства. Память `O(n + m)` сверх матрицы ответа `O(n²)`.

### Связь с домашним заданием

[task_04](../../task_04/README.md) — ровно этот алгоритм: при отрицательном цикле в **любой** части графа выводить `NEGATIVE CYCLE` (шаг 2), недостижимые пары — `INF`, на диагонали 0. Напомнить про 64-битные целые: сами ответы помещаются в 32 бита, но `δ_h` и суммы с `INF` — нет. Флойд как решение задачи не засчитывается, но им удобно проверять ответы в своих тестах.

## 7. Сравнение сложности и выбор алгоритма — 7 минут

| Алгоритм | Задача | Веса | Время | Доп. память |
|---|---|---|---|---|
| BFS | один источник | все 1 | `O(n + m)` | `O(n)` |
| Релаксация в порядке топсорта | один источник, DAG | любые | `O(n + m)` | `O(n)` |
| Дейкстра, массив | один источник | `>= 0` | `O(n² + m)` | `O(n)` |
| Дейкстра, бинарная куча | один источник | `>= 0` | `O((n + m) log n)` | `O(n)` (`O(n + m)` с повторными записями) |
| Форд—Беллман (+ поиск `-∞`) | один источник | любые | `O(nm)` | `O(n)` |
| Флойд—Уоршелл | все пары | любые | `O(n³)` | `O(n²)` |
| `n` × Дейкстра (куча) | все пары | `>= 0` | `O(n(n + m) log n)` | `O(n + m)` + ответ |
| Джонсон | все пары | любые | `O(n(n + m) log n)` | `O(n + m)` + ответ |

Подробная таблица с вариантами Дейкстры (повторные записи, фибоначчиева куча) и численными ориентирами — в [конспекте лекции 7](lecture_07.md), раздел 9; на лекции 7 она не разбиралась, при желании раздать как справочный материал.

Ориентир на числах (порядок `10⁸` простых операций в секунду):

| Ограничения | Флойд `n³` | Джонсон `n(n + m) log n` | Вывод |
|---|---:|---:|---|
| `n = 400`, `m ≈ 1.6·10⁵` | `6.4·10⁷` | `≈ 5.5·10⁸` | Флойд |
| `n = 3000`, `m = 6000` | `2.7·10¹⁰` | `≈ 3.1·10⁸` | Джонсон |

Вычисления: `400 · (400 + 1.6·10⁵) · 8.6 ≈ 5.5·10⁸`; `3000 · 9000 · 11.6 ≈ 3.1·10⁸` (`log₂ 400 ≈ 8.6`, `log₂ 3000 ≈ 11.6`).

| Задача | Выбор |
|---|---|
| один источник, `w >= 0` | Дейкстра: куча на разреженном графе, массив на плотном |
| один источник, есть отрицательные дуги | Форд—Беллман, он же находит цикл и `-∞` |
| один источник, граф ацикличен | релаксация в порядке топсорта, `O(n + m)` |
| все пары, плотный граф или `n` до нескольких сотен | Флойд—Уоршелл — короче код, меньше ошибок |
| все пары, разреженный граф | `n` × Дейкстра; при отрицательных дугах — Джонсон |

Итоговая фраза: Форд—Беллман повторяет релаксации, Флойд расширяет множество промежуточных вершин, Джонсон убирает отрицательные веса потенциалом и сводит задачу к Дейкстре.

## 8. Контрольные вопросы — вместе с самостоятельной работой в последние 5 минут

| Вопрос | Ответ |
|---|---|
| Что означает улучшение на `n`-м проходе? | из `s` достижим отрицательный цикл, у улучшенной вершины `δ = -∞` |
| Лежит ли улучшенная вершина на цикле? | не обязательно — поэтому `n` шагов по предкам |
| Все ли вершины с `-∞` улучшаются на `n`-м проходе? | нет: пример E, вершина `d`; нужен обход из улучшенных |
| Влияет ли недостижимый из `s` отрицательный цикл на ответы из `s`? | нет; но на задачу всех пар — да |
| Зачем во Флойде `k` — внешний цикл? | динамика по множеству промежуточных вершин `{1..k}` |
| Почему Флойду хватает одной матрицы? | строка и столбец `k` на фазе `k` не меняются при `dist[k][k] >= 0` |
| Как Флойд обнаруживает отрицательный цикл? | `dist[v][v] < 0` хотя бы для одной `v` |
| Когда пара `(i, j)` получает `-∞`? | есть `t` с `dist[t][t] < 0`, достижимая из `i`, из которой достижима `j` |
| Почему в Джонсоне `w + h(u) - h(v) >= 0`? | неравенство треугольника для расстояний от `q` |
| Зачем вершина `q`, а не Форд—Беллман из вершины `1`? | иначе часть вершин недостижима и `h = ∞` |
| Сколько проходов Форда—Беллмана в Джонсоне? | `n` и проверочный — в графе `n + 1` вершина |

## Типичные ошибки

- Релаксировать из `d[u] = ∞` — `INF + (отрицательное)` даёт фальшивый маршрут.
- Объявлять `-∞` только вершинам, улучшенным на `n`-м проходе (пример E: `d`).
- Восстанавливать цикл сразу от улучшенной вершины, без `n` шагов назад — можно попасть на «хвост» и зациклиться не там.
- Идти по `parent` или `next` к вершине или паре с ответом `-∞` — бесконечный цикл.
- Во Флойде: `k` во внутреннем цикле; обнулить диагональ, потеряв отрицательную петлю; не брать минимум по параллельным дугам; складывать с `∞`.
- В Джонсоне: `n - 1` проход для графа из `n + 1` вершины; потенциал из произвольной вершины; забыть обратный пересчёт; пересчитывать `INF` (недостижимые пары остаются `INF`); 32-битные `δ_h`.
- Считать, что Флойд «сам выдаст `-∞`» — без явной классификации числа при отрицательных циклах бессмысленны.

## 9. Резерв на 5 / 10 / 20 минут

### Блок A — 5 минут: кратчайшие пути в DAG

Если граф ацикличен, достаточно одного прохода релаксации в порядке топологической сортировки (лекция 2): к моменту обработки `u` все дуги, входящие в `u`, уже отрелаксированы, поэтому `d[u]` окончательна. Время `O(n + m)`, отрицательные веса разрешены — циклов нет.

Пример B лекции 6 — DAG. Топологический порядок `s, b, a, t`: из `s` — `a = 2`, `b = 5`; из `b` — `a = min(2, 1) = 1`, `t = 11`; из `a` — `t = min(11, 4) = 4`. Ответ `(0, 1, 5, 4)`, как у Форда—Беллмана, но за один проход.

Длиннейший путь в DAG — тот же алгоритм с заменой `w` на `-w` (или `min` на `max`). В графе с циклами так нельзя: задача о длиннейшем простом пути NP-трудна.

**Точка остановки:** связь с топсортом и оценка `O(n + m)`.

### Блок B — ещё 5 минут: транзитивное замыкание

Та же схема Флойда, но над булевыми значениями (алгоритм Уоршелла):

```text
reach[i][j] = (i == j) or есть дуга i → j
for k: for i: for j:
    reach[i][j] = reach[i][j] or (reach[i][k] and reach[k][j])
```

Доказательство дословно повторяет раздел 4 с заменой `min` на `or` и `+` на `and`. Пример: `1 → 2`, `2 → 3`, `3 → 1`, `3 → 4`. Итог: из `1`, `2`, `3` достижимы все четыре вершины; из `4` — только `4`. Строку матрицы можно хранить битсетом: `reach[i] |= reach[k]`, если `reach[i][k]`, — это `O(n³ / 64)`.

**Точка остановки:** схема «Флойд над другой операцией» и битсеты.

### Блок C — ещё 10 минут: minimax-пути и связь с MST

**Minimax-путь** — путь, у которого максимальный вес ребра минимален (например, самая «низкая» дорога для высокого грузовика). Та же схема Флойда с `min` и `max`:

```text
mm[i][i] = -∞, mm[i][j] = w(i, j) или ∞
mm[i][j] = min(mm[i][j], max(mm[i][k], mm[k][j]))
```

Пример — неориентированный граф: `A—B (4)`, `B—C (2)`, `A—C (5)`, `C—D (1)`, `B—D (6)`. Minimax `A ⇝ D` равен 4 (путь `A—B—C—D`); альтернативы: `A—C—D` с максимумом 5, `A—B—D` с максимумом 6.

**Связь с MST (подводка к лекции 9).** Минимальное остовное дерево этого графа — `{C—D 1, B—C 2, A—B 4}`; путь `A ⇝ D` в нём — `A—B—C—D`, максимум 4. Это не совпадение: в **неориентированном** графе путь между `u` и `v` в минимальном остовном дереве — minimax-путь.

Подсказка к доказательству: пусть на пути в MST максимальное ребро `e`, а существует путь с максимумом `b < w(e)`. Удалим `e` из дерева — оно распадётся на две части, а путь с максимумом `b` где-то пересекает разрез ребром `f`, `w(f) <= b < w(e)`. Замена `e` на `f` даёт остовное дерево меньшего веса — противоречие. Само утверждение о разрезе — тема лекции 9.

Для ориентированных графов это неверно: остовного дерева в нужном смысле нет. Максиминный путь («самая широкая дорога») в неориентированном графе аналогично лежит в **максимальном** остовном дереве.

**Точка остановки:** схема `min/max` и формулировка связи с MST; доказательство через разрез можно оставить на лекцию 9.
