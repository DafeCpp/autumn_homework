# Опорный конспект к лекции 5. Завершение обходов графа и обзор планарности

Связанные материалы: [лекция 4](lecture_04.md), [план курса](../lecture_plan.md).

## Откуда начинаем

На лекции 4 прошли мосты и точки сочленения, обсудили эйлеров цикл и критерий его существования. Компоненты двусвязности считаем оставшейся частью предыдущего плана. Доказательство Тарьяна для SCC по-прежнему отложено на конец семестра, только при наличии времени.

Критерий эйлерова цикла уже известен: восстановить его двумя вопросами о чётности и связности, затем перейти к незамкнутому пути. Основной новый материал этой части — алгоритм построения, его трассировка и обоснование. Эйлеровы пути занимают компактный блок этой пары. Планарность включена как десятиминутный обзор; отдельной лекции, полного гамма-алгоритма и доказательств структурных критериев сейчас не планируем.

Фраза для начала: «Мы научились находить места, где граф распадается при удалении ребра или вершины. Теперь соберём его устойчивые части, а затем закончим другую задачу: как пройти по всем рёбрам ровно один раз».

Обозначения: `n = |V|`, `m = |E|`. В разделе о вершинных блоках граф простой и неориентированный. Для эйлеровых маршрутов разрешены кратные рёбра и петли; у каждого ребра свой `id`, петля даёт вклад 2 в неориентированную степень.

## Цели и тайминг на 90 минут

1. Различать рёберные компоненты и вершинные блоки; уметь выделить их по результатам DFS.
2. Проверять существование эйлерова пути и цикла, учитывая связность и правильный старт.
3. Объяснить алгоритм Хиерхольцера, обратный порядок ответа и оценку `O(n + m)`.
4. Познакомиться с плоской укладкой, гранями и формулой Эйлера на уровне обзора.

| Время | Тема | Что оставить на доске |

Эйлеровым маршрутам отведено 30 минут: известный критерий не доказываем заново. Подробный код и обоснования ниже — опора преподавателю; на доске достаточно идеи вставки циклов, одной трассировки и объяснения линейности. Планарность ограничить обзором из раздела 7.

**Если идём медленнее:** не переписывать целиком псевдокод блоков и Хиерхольцера; сохранить одну трассировку каждого. Сократить закрепление, а обзор планарности — до определения, рисунка `K4` и формулы Эйлера. Подробности планарности не становятся обязательным продолжением следующей пары.

Резерв занимает освободившееся время внутри 90 минут; последние 5 минут сохранить для итогов. Если углублять планарность не хочется, можно сразу взять независимый блок C.

## 1. Входные вопросы и сквозной пример

На доске восстановить три правила без повторения полных доказательств:

- древесное ребро `v—to` — мост при `low[to] > tin[v]`;
- некорневая `v` — точка сочленения, если есть ребёнок `to` с `low[to] >= tin[v]`;
- корень — точка сочленения при двух или более детях **DFS**, независимо от его степени.

Вопрос: «Возврат из поддерева ровно в `v` спасает ребро? А саму вершину?» Ответ: ребро можно обойти, но после удаления `v` этот возврат исчезает.

### Пример B из прошлой лекции

```text
Треугольник: 0—1, 1—2, 2—0.
Перемычка:  1—3.
Треугольник: 3—4, 4—5, 5—3.
Хвост:      3—6.
Вершина 7 изолирована.
```

При стартах и соседях по возрастанию: `tin = [0,1,2,3,4,5,6,7]`, `low = [0,0,0,3,3,3,6,7]`. Мосты — `1—3` и `3—6`, точки сочленения — `1` и `3`. Значения выдать готовыми после входных вопросов: сегодня цель — получить компоненты, а не заново вычислить весь DFS.

## 2. Компоненты двусвязности

### Рёберная двусвязность

Удаляем все мосты и запускаем обычный DFS/BFS. Полученные множества вершин — компоненты рёберной двусвязности; одиночные вершины допускаем. Внутри каждой удаление одного ребра не нарушает связность. Это разбиение **вершин**, а мосты соединяют разные компоненты.

В примере B: `{0,1,2}`, `{3,4,5}`, `{6}`, `{7}`. Если сжать их, мосты образуют лес: цикл из мостов дал бы обход каждого из них, что невозможно. На каждую исходную связную компоненту приходится одно дерево этого леса.

Нахождение мостов и повторный обход суммарно занимают `O(n + m)`.

### Вершинная двусвязность и блоки

Для этого подраздела берём простой неориентированный граф. Блоки — максимальные связные подграфы без собственных точек сочленения. Используем соглашение: мост с концами — отдельный блок из двух вершин, изолированная вершина — отдельный одноэлементный блок. Невырожденные двусвязные блоки содержат не менее трёх вершин.

Блоки могут пересекаться по точкам сочленения. Каждое ребро принадлежит ровно одному блоку; вершина может принадлежать нескольким. Нельзя получить блоки простым удалением точек сочленения: они входят в сами блоки.

В примере B блоки по множествам вершин: `{0,1,2}`, `{1,3}`, `{3,4,5}`, `{3,6}`, `{7}`.

### Как выделять блоки стеком рёбер

Дополняем неориентированный DFS отдельным стеком `edgeStack`:

1. Перед рекурсией по древесному ребру кладём его `id` в стек.
2. Недревесное ребро кладём только при просмотре из потомка к предку (`tin[to] < tin[v]`), чтобы не положить его дважды. Ребро прихода по-прежнему пропускаем.
3. После возврата из ребёнка `to`, если `low[to] >= tin[v]`, снимаем рёбра до древесного `v—to` включительно. Это один блок; его вершины — концы снятых рёбер.
4. Изолированную вершину выдаём отдельно: она не положит в стек ни одного ребра.

Условие извлечения блока используется **и для корня**. Специальное правило о двух детях нужно только для отметки корня как точки сочленения.

Идея корректности: при `low[to] >= tin[v]` накопленная часть не соединяется со строгими предками `v` в обход `v`, поэтому здесь проходит граница блока. Более глубокие границы уже обработаны; оставшиеся сверху рёбра образуют очередной максимальный блок.

В примере B при возврате из `2` блок ещё не снимается; при возврате из `4` снимается треугольник `{3,4,5}`, из `6` — ребро `3—6`, из `3` — ребро `1—3`, из `1` — треугольник `{0,1,2}`.

Каждое ребро кладётся и снимается один раз, время — `O(n + m)`, память для стека и результата — `O(n + m)`. Для выдачи уникальных вершин блока можно использовать массив меток с номером текущего блока, не очищая массив размера `n` на каждом извлечении.

### Псевдокод выделения вершинных блоков

Отдельный запуск DFS по простому неориентированному графу. В `blocks` храним списки идентификаторов рёбер, изолированные вершины выдаём отдельно. Для каждого ребра известны его концы.

```text
timer = 0
tin = [-1] * n
low = [-1] * n
edgeStack = []
blocks = []

blocksDfs(v, parentEdge):
    tin[v] = low[v] = timer++
    for (to, id) in adj[v]:
        if id == parentEdge:
            continue
        if tin[to] == -1:
            edgeStack.push(id)
            blocksDfs(to, id)
            low[v] = min(low[v], low[to])
            if low[to] >= tin[v]:
                block = []
                repeat:
                    e = edgeStack.pop()
                    block.push(e)
                until e == id
                blocks.push(block)
        else if tin[to] < tin[v]:
            edgeStack.push(id)
            low[v] = min(low[v], tin[to])

for v in vertices:
    if tin[v] == -1:
        if adj[v] is empty:
            outputSingleton(v)
        blocksDfs(v, -1)
```

После завершения каждой связной компоненты стек пуст. Не добавлять условие «корень имеет два ребёнка» к извлечению блока: даже треугольник с одним ребёнком корня должен быть выдан.

Вопрос для перехода: «Два треугольника с общей вершиной: сколько рёберных компонент и сколько вершинных блоков?» Ответ: одна рёберная компонента, два блока. Общая вершина — точка сочленения, но эйлеров цикл в этом графе есть.

## 3. Эйлеровы пути: неориентированный случай

Критерий цикла восстановить с аудиторией за 1–2 минуты. Определения и обоснование ниже служат опорой преподавателю; заново читать их целиком не нужно. Основной акцент — две нечётные вершины и сведение пути к циклу.

Эйлеров путь — маршрут, использующий каждое ребро ровно один раз. Вершины повторяться могут. Если начало совпадает с концом, это эйлеров цикл. Под «незамкнутым путём» ниже понимаем маршрут с различными концами.

При `m > 0` все вершины ненулевой степени должны лежать в одной компоненте связности. Изолированные вершины не мешают.

| Что ищем | Дополнительное условие | Откуда начинать |
|---|---|---|
| Цикл | все степени чётны | любая вершина ненулевой степени |
| Незамкнутый путь | ровно две нечётные вершины | одна из нечётных вершин |
| Путь, возможно замкнутый | 0 или 2 нечётные вершины | по одному из правил выше |

**Необходимость:** в каждой внутренней вершине приход спаривается с уходом. Только разные начало и конец имеют по одному неспаренному инцидентному ребру. Все использованные рёбра принадлежат одной связной части.

**Переход к достаточности:** при двух нечётных вершинах `s,t` добавить фиктивное ребро с новым `id` между ними. Все степени станут чётными. После построения цикла разрезать его по этому ребру и удалить его; получится путь исходного графа. Даже если ребро `s—t` уже есть, фиктивное ребро отличается идентификатором.

Три коротких примера:

1. Два треугольника `0—1—2—0` и `0—3—4—0`: все степени чётны, цикл есть; точка сочленения `0` не мешает.
2. Добавляем хвост `4—5`: нечётны только `4` и `5`, теперь есть незамкнутый путь.
3. Два раздельных треугольника: степени чётны, общего эйлерова цикла нет.

Отсутствие мостов само по себе недостаточно: у `K4` все четыре степени равны 3. Для неориентированного эйлерова цикла мостов действительно быть не может, но проверка критерия степеней и связности проще и полнее.

## 4. Алгоритм Хиерхольцера

### Идея: вставлять замкнутые обходы

Для графа с чётными степенями начать идти по неиспользованным рёбрам. Вне стартовой вершины застрять нельзя: каждому приходу можно сопоставить уход. Максимальный такой проход замкнётся в старте.

Если рёбра остались, связность гарантирует вершину уже построенного маршрута, инцидентную неиспользованному ребру. Строим из неё новый замкнутый проход и вставляем в прежний. После удаления рёбер замкнутого прохода степени оставшихся рёбер остаются чётными. Повторяем до исчерпания рёбер.

Стек реализует эти вставки без ручного склеивания списков: вершину добавляем в ответ только тогда, когда из неё больше нет неиспользованных рёбер. Получается обратный порядок, поэтому ответ разворачиваем.

### Псевдокод

До запуска проверить критерий и выбрать старт. При `m = 0` отдельно вернуть одну произвольную вершину, если `n > 0`, иначе пустой маршрут; это соглашение для вырожденного случая.

Каждое неориентированное ребро хранится в обеих записях смежности с одним `id`. Петлю также можно хранить двумя записями; `used[id]` не даст пройти её дважды.

```text
used = [false] * m
ptr = [0] * n
stack = [start]
answer = []

while stack is not empty:
    v = stack.top()
    while ptr[v] < len(adj[v]) and used[adj[v][ptr[v]].id]:
        ptr[v] += 1
    if ptr[v] == len(adj[v]):
        answer.push(stack.pop())
    else:
        (to, id) = adj[v][ptr[v]]
        ptr[v] += 1
        used[id] = true
        stack.push(to)

answer.reverse()
if len(answer) != m + 1:
    report "Маршрута по всем рёбрам нет"
else:
    output(answer)
```

Прямой запуск из нечётной вершины строит открытый путь без добавления фиктивного ребра; фиктивное ребро удобно для доказательства. Если нужен ответ в виде рёбер, хранить вместе с вершиной стека `id` ребра, которым в неё вошли, и собирать эти `id` при снятии со стека.

### Трассировка, показывающая смысл обратного ответа

Берём два треугольника с хвостом из раздела 3, стартуем из `4` и **сначала выбираем ребро `4—5`**.

| Действие | Стек | Ответ до разворота |
|---|---|---|
| Старт | `[4]` | `[]` |
| Прошли `4—5` | `[4,5]` | `[]` |
| В `5` больше нет рёбер: снимаем её | `[4]` | `[5]` |
| Продолжаем через `4,3,0,1,2,0,4` | `[4,3,0,1,2,0,4]` | `[5]` |
| Все оставшиеся вершины снимаются | `[]` | `[5,4,0,2,1,0,3,4]` |

После разворота: `4,3,0,1,2,0,4,5`. Все семь рёбер использованы ровно один раз. Уход в лист в начале не испортил результат: ребро к листу оказалось в конце ответа.

Это основной пример пары: он объясняет, почему текущий стек и готовый маршрут — разные вещи, а выбор первого ребра не требует проверки мостов.

### Корректность и сложность

Для цикла достаточность критерия следует из последовательной вставки замкнутых проходов: каждый новый проход использует только свежие рёбра, а связность не позволяет оставить рёбра вне построения. Стек реализует те же вставки, записывая уже завершённые части в обратном порядке. Для открытого пути применяется сведение с фиктивным ребром; при прямом запуске из нужного конца терминальный участок также записывается первым и после разворота оказывается последним.

`used[id]` обеспечивает однократное использование ребра. Указатели `ptr[v]` только растут: суммарно просматриваются `2m` записей для неориентированного графа. В стек добавляется старт и по одной вершине на каждое использованное ребро, затем каждое вхождение один раз снимается.

Время с проверкой условий — `O(n + m)`, память — `O(n + m)`. Стек здесь может содержать `m + 1` вхождений, потому что вершины повторяются.

Проверка длины `m + 1` подтверждает использование всех рёбер **при выполненных условиях степеней и верном старте**. Она сама по себе не заменяет эти условия: алгоритм на неподходящем графе может выдать последовательность нужной длины, где соседние вершины не соединены ребром. Контрпример — звезда с тремя листьями, старт из центра.

## 5. Ориентированный случай

Определим `delta[v] = outdeg[v] - indeg[v]`. Для вершин ненулевой суммарной степени требуется слабая связность.

| Маршрут | Условия | Старт |
|---|---|---|
| Цикл | все `delta[v] = 0` | любая вершина с исходящим ребром |
| Незамкнутый путь `s → t` | `delta[s] = 1`, `delta[t] = -1`, у остальных 0 | `s` |

Необходимость: каждый приход должен быть уравновешен уходом, кроме начала и конца открытого маршрута. Для открытого случая добавить дугу `t → s`, получить цикл и разрезать его по добавленной дуге.

Для цикла слабой связности и баланса достаточно. Связь с SCC из лекции 3: рассмотрим источник конденсации. Сумма `outdeg - indeg` по его вершинам равна числу внешних исходящих дуг минус число внешних входящих. Входящих нет; баланс запрещает и исходящие. При нескольких SCC это противоречит слабой связности. Значит, активные вершины лежат в одной SCC. Теперь применяется та же идея вставки замкнутых проходов.

Код Хиерхольцера остаётся тем же, но в списках смежности хранятся только исходящие дуги. Пример: `0 → 1 → 2 → 0`, `0 → 3`. Балансы `+1` у `0`, `-1` у `3`; путь `0,1,2,0,3`. Сам исходный граф открытого пути не обязан быть сильно связным.

## 6. Контрольные вопросы

| Вопрос | Ответ |
|---|---|
| Рёберные компоненты могут иметь общую вершину? | нет; вершинные блоки могут пересекаться по точке сочленения |
| Почему блок снимаем и при равенстве `low[to] = tin[v]`? | обход доходит до `v`, но не к её строгим предкам |
| Точка сочленения запрещает эйлеров цикл? | нет: два треугольника с общей вершиной |
| Все степени чётны — этого достаточно? | нужна ещё связность вершин с рёбрами |
| Можно ли стартовать с любой вершины открытого пути? | нет: с нечётной, а в орграфе — с балансом `+1` |
| Зачем `id`, если известны концы ребра? | параллельные рёбра различны, две записи одного ребра — нет |
| Зачем `ptr`? | чтобы повторно не просматривать список с самого начала |
| Почему нельзя сразу печатать вершины при движении? | ранний заход в тупик может быть концом окончательного маршрута |

## 7. Краткий обзор планарности — 10 минут

Переход: «Эйлеров маршрут отвечает на вопрос, как пройти по графу. Теперь спросим, можно ли нарисовать его на плоскости без пересечения рёбер». Эйлеров цикл и формула Эйлера — разные понятия.

**Первые 5 минут — рисунки и определения.** Планарный граф допускает рисунок на плоскости, в котором рёбра пересекаются только в общих концах. Плоская укладка — конкретный такой рисунок. Грани — связные области дополнения рисунка; внешняя неограниченная область тоже считается гранью.

Нарисовать `K4` как квадрат с двумя диагоналями, затем как треугольник с четвёртой вершиной внутри. Соединить внутреннюю вершину с углами: пересечений нет, граней четыре. Пересечение рёбер на неудачном рисунке не доказывает непланарность графа. Добавлять новую вершину в пересечение — значит менять граф.

**Следующие 5 минут — формула и ориентиры.** Для связного плоского графа сформулировать без доказательства `n - m + f = 2`; проверить на `K4`: `4 - 6 + 4 = 2`. У дерева одна грань, включая внешнюю. Формула применяется к укладке и сама по себе не служит алгоритмом проверки планарности.

Показать два стандартных непланарных графа: `K5` — пять попарно соединённых вершин; `K3,3` — две тройки, все девять рёбер идут между тройками. Их непланарность сейчас сообщить как факт, доказательства оставить в резерве. Теоремы Понтрягина—Куратовского и Вагнера, детали алгоритмов укладки и полный гамма-алгоритм в обзор не включать.

**Точка остановки:** понятие планарности, грани, формула и два примера известны. Этого достаточно для текущего плана; следующая основная тема — взвешенные кратчайшие пути.

## 8. Запасной материал — до 20 минут

Блоки A и B необязательны: они углубляют обзор только при желании и наличии времени. Блок C независим и позволяет сразу перейти к следующей теме курса.

### Блок A — 5 минут: доказательство формулы Эйлера

Для связного плоского графа:

```text
n - m + f = 2
```

Короткое доказательство: пока есть цикл, удалять ребро этого цикла. Связность сохраняется, две соседние грани сливаются, поэтому `m` и `f` уменьшаются на 1, а `n - m + f` не меняется. В конце остаётся дерево: `m = n - 1`, `f = 1`, значит значение равно 2.

Для `c` компонент связности формула имеет вид `n - m + f = 1 + c`: можно добавить `c - 1` рёбер между компонентами, не создавая новых граней, и применить связный случай.

Проверка на `K4`: `4 - 6 + 4 = 2`. У дерева только внешняя грань; мост не разделяет две разные грани, поэтому в доказательстве удаляем именно ребро цикла.

**Точка остановки:** формула доказана; к дополнительным следствиям переходить только при наличии времени.

### Блок B — ещё 10 минут: следствия и два непланарных графа

Для простого связного планарного графа при `n >= 3` каждая граница грани имеет длину не меньше 3, а сумма длин границ равна `2m`. Ребро-мост учитывается дважды на границе одной грани. Следовательно, `3f <= 2m`; вместе с формулой Эйлера это даёт:

```text
m <= 3n - 6
```

Для простого связного двудольного планарного графа при `n >= 3` граница грани не может иметь нечётную длину, а минимальная длина здесь не меньше 4. Поэтому `4f <= 2m` и:

```text
m <= 2n - 4
```

У дерева с `n >= 3` единственная граница имеет длину `2(n - 1) >= 4`, так что мосты не мешают второму рассуждению. Простота графа и ограничение на `n` существенны: петли, кратные рёбра и граф из одного ребра нельзя подставлять в эти оценки без оговорок.

| Граф | Число вершин и рёбер | Противоречие |
|---|---|---|
| `K5` | `n = 5`, `m = 10` | `10 > 3·5 - 6 = 9` |
| `K3,3` | `n = 6`, `m = 9`, граф двудольный | `9 > 2·6 - 4 = 8` |

Уточнить: выполнение оценки **не доказывает планарность**. Уже `K3,3` удовлетворяет общей оценке `9 <= 12`, но непланарен. Более сильный пример: разделить каждое из девяти рёбер `K3,3` новой вершиной. Получим двудольный граф с `n = 15`, `m = 18`, удовлетворяющий обеим оценкам, но по-прежнему непланарный: из его укладки можно было бы убрать вершины степени 2 и получить укладку `K3,3`.

**Точка остановки:** доказана непланарность двух примеров. На этом углубление в планарность заканчиваем; полного гамма-алгоритма в текущем плане нет.

### Блок C — ещё 5 минут: зачем нужен алгоритм Дейкстры

Нарисовать ориентированный граф с весами: `s → t` вес 10, `s → a` вес 1, `a → t` вес 1. BFS минимизирует число рёбер и выбирает прямую дугу, но минимальный суммарный вес равен 2 и достигается через `a`.

Ввести расстояние `d[v]`, начальные значения `d[s] = 0`, у остальных бесконечность, и релаксацию дуги:

```text
если d[u] + w(u,v) < d[v]:
    d[v] = d[u] + w(u,v)
    parent[v] = u
```

Вопрос: «В каком порядке обрабатывать вершины, чтобы не возвращаться к уже окончательным расстояниям?» Обозначить идею Дейкстры: выбирать необработанную вершину с наименьшей текущей оценкой. Условие неотрицательности весов, доказательство и реализацию разобрать на следующей лекции.

**Точка остановки:** постановка и релаксация известны; на лекции 6 можно сразу перейти к алгоритму Дейкстры.
