# Установщик приложений и библиотек

Команда разрабатывает набор приложений и библиотек. Некоторые компоненты нельзя установить самостоятельно: перед ними необходимо установить все их зависимости.

Например, приложение `A` зависит от библиотеки `B`, а `B` зависит от библиотеки `C`. Тогда компоненты нужно устанавливать в порядке `C`, `B`, `A`.

Требуется построить допустимый порядок установки всех компонентов. Если зависимости циклические и установить компоненты невозможно, нужно вывести `-1`.

## Формат ввода

В первой строке заданы два целых числа `n` и `m` — количество компонентов и зависимостей (`1 ≤ n ≤ 2⋅10⁵`, `0 ≤ m ≤ 2⋅10⁵`).

Компоненты пронумерованы от `0` до `n-1`. Каждый компонент может быть приложением или библиотекой; для задачи различать их типы не требуется.

В следующих `m` строках заданы пары чисел `a b` (`0 ≤ a, b < n`). Такая пара означает, что компонент `a` зависит от компонента `b`, поэтому `b` должен быть установлен раньше `a`.

Зависимости могут состоять из нескольких независимых цепочек. Компонент также может не иметь зависимостей. Запись `a a` является циклической зависимостью.

## Формат вывода

Если установить все компоненты возможно, выведите `n` чисел — их номера в допустимом порядке установки. Для каждой входной зависимости `a b` число `b` должно находиться в ответе раньше числа `a`.

Если допустимых порядков несколько, можно вывести любой из них.

Если зависимости содержат цикл, выведите `-1`.

## Пример 1

Ввод:

```text
3 2
0 1
1 2
```

Вывод:

```text
2 1 0
```

Компонент `0` зависит от `1`, а `1` — от `2`, поэтому сначала устанавливается `2`.

## Пример 2

Ввод:

```text
4 4
0 1
1 2
2 0
3 1
```

Вывод:

```text
-1
```

Компоненты `0`, `1` и `2` образуют цикл зависимостей, поэтому корректного порядка установки не существует.
